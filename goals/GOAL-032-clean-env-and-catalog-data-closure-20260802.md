# GOAL-032 干净环境可复现性与产品目录正式值收口

Status: `in_progress`

Mode: `stage-goal`

## Summary

本 Goal 处理一类此前未被覆盖的缺口：**代码本身可用，但"从零到能跑"这条路从未被验证过**。

2026-08-02 在一台全新 macOS 机器上按 `README.md` 从零安装本项目，连续踩到三个阻塞问题：演示环境写死关闭 AI、`demo:seed` 两步顺序颠倒导致全新库必然失败、`demo:seed` 场景 07 账单重复绑定返回 409。三个问题都不是功能缺陷，而是**只在已配置好的开发机上不会暴露的可复现性缺陷**。

真实部署到客户服务器就是一次"全新环境从零跑通"。这些问题不提前排掉，会在客户在场时原样复现。

同时收口一项长期挂起的数据缺口：产品配置中心（V75 / D-178）结构已就绪但正式业务值为空，导致管理端"产品总览"在客户验收时表现为"无数据"。

本 Goal 不新增业务功能，不改变任何已验收的业务语义，不改变 Task 8 的 `NOT_READY` 状态。

## Scope

- A：把 2026-08-02 已完成的两处可复现性修复提交回远端，使 Codespace 与本地一致。
- B：修复 `demo:seed` 场景 07 账单重复绑定 409，使 7 个场景在全新库上连续通过。
- C：按《动态下单表最终版》为产品配置中心补充正式业务值草稿，覆盖 6 个产品大类、约 50 个产品一类及其材料、牙色与制作要求选项。
- D：建立并执行"干净机器全流程演练"，形成可重复执行的检查入口，纳入 `deployment-infrastructure` readiness 证据。

## Non-goals

- 不新增业务功能，不改动订单、工序、质检、工时、账单、物流、设计稿任何已验收语义。
- 不实现《角色权限客户确认清单》中的角色与权限改造（组长层级、账号交接、收货/发货岗位等），另立 Goal。
- 不补造客户尚未提供的业务数据：文件上传规则（该文档第四页为空）、价格与制作周期（第六页为空）、各工序标准工时。这些项必须保持 `DRAFT` / `INACTIVE` / "待报价" / "待设置"。
- 不改动工序链结构、节点顺序或 DAG。
- 不提交 `.env`、DeepSeek API Key、数据库密码、MinIO 密钥或任何真实凭据。
- 不 push 到 `main`。
- 不把本地演练结果写成真实服务器部署验收，不把 Task 8 改为 `READY`。

## Acceptance

- 在一台未配置过本项目的机器上，**只按 `README.md` 操作、不做任何手动补救**，可完成：依赖安装 → 基础服务启动 → 后端编译 → 四端登录 → `demo:prepare` 7 个场景全部通过。
- `demo:backend` 不再硬编码关闭 AI；未注入 `AI_PROVIDER` 时默认仍为 `deterministic`，注入后可切换到 `langchain-deepseek`。
- `npm run demo:seed` 在全新库上从第一步到最后一步连续通过，且**可重复执行不报 409**。
- 管理端"产品总览"与"下单内容设置"可见符合《动态下单表最终版》的正式产品与材料层级；未提供价格的项目显示"待报价"，未提供文件规则的项目显示"待设置"，无虚构金额与虚构规则。
- 新增 `npm run check:clean-env-reproducibility` 作为本 Goal 的检查入口。
- 客户资料指纹与提取文本归档进仓库，原始文件失效后仍可追溯。
- Task 8 保持 `NOT_READY`。

## Risks

- 产品目录正式值体量大（材料品牌型号数百项），人工录入易错；必须提供可复核的导入清单与校验脚本，不接受逐条手工点击。
- 《动态下单表最终版》第四页（各大类上传资料）与第六页（价格 / 默认要求 / 制作周期）为空白，属于客户未交付内容，会导致 C 批次只能完成部分字段；该缺口继续计入 CP-002 / CP-005，不得用占位值掩盖。
- 干净机器演练需要一个隔离环境；若使用 Docker 容器模拟，需注意 macOS 与 Linux 的 JDK / Docker-in-Docker 差异，演练结论要标注宿主平台。
