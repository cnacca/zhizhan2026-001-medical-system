# GOAL-031 产品目录 V2 与病例订单组全链改造

Status: `in_progress`

Mode: `stage-goal`

## Summary

按 D-174/D-175 已批准的“病例订单组 + 产品子订单”模型，把客户产品资料、动态下单表、现有单产品订单和九条业务链整合为可配置、可审计、兼容历史数据的下单与生产闭环。

本 Goal 使用 `order_case_group` 承载医生看到的病例级订单组，继续保留 `orders` 作为每个产品真实执行的子订单。客服初审、生产审核、设计、生产、质检、账单和物流仍逐子订单执行，订单组只提供草稿、共享资料、聚合状态和医生外部投影。

## Scope

- A：需求基线与产品目录标准化。
- B：病例订单组与历史单产品订单兼容模型。
- C：产品配置中心、产品目录 V2、动态表单 V2、版本化计价和组级/子单级文件规则。
- C2：现有九条工序链节点的标准工时维护底座、版本草稿与实例快照能力；正式数据到位前隐藏菜单并禁用发布/计算。
- D：订单组 API 与医生端多产品向导。
- E：固定、种植、活动、常规正畸和设计服务等普通产品闭环。
- F：隐形正畸七步向导、方案版本、内审、医生确认、批次和调整申请。
- G：D-173 权限、DataScope、外部投影、审计和消息隔离。
- H：非破坏迁移、OpenAPI、自动化、真实浏览器全链和交付文档。

## Non-goals

- 不删除、重命名或重建现有 `orders`，不迁移或删除历史工序、设计稿、质检、工时、返工、账单、物流和审计事实。
- 不把订单组做成共用一个生产状态的“大订单”。
- 不开放现有工序链节点的增删、排序、拖拽或 DAG 编辑；标准工时维护不等于动态编辑工序链模板。
- 不把材料、颜色或普通配件误建为成品 SKU；只有独立生产、计价、库存、发货或返工时，配件才升级为子订单。
- 不把占位价当正式报价，不自动重算历史订单或最终账单。
- 不引入积分、患者绑定、佩戴建议、高级 Web 3D 编辑、自动支付或外部物流集成。
- 不替换现有鉴权运行时，不覆盖独立 M2 worktree 的 RuoYi 权限、DataScope、审计或文档改动。
- 不把本地自动化或浏览器通过写成真实生产环境验收，不把 Task 8 改为 READY。

## Acceptance

- 每个目录项有稳定 code、显示名、类别、状态及适用的变体、材料、配件、牙位、字段和上传规则；`Full Denture / Complete Denture` 归并为一个“全口义齿”SKU，`Lucitone 199` 只作为材料品牌/规格。
- 管理端“产品配置中心”可新增、修改、逻辑停用、恢复、排序、复制、绑定、预览和发布分类/产品/变体/材料/配件及规则；发布生成不可变版本，非法物理删除返回 409，维护与发布均有独立权限和完整审计。
- 新增材料绑定两个产品后，医生端只在适用产品显示；停用后新草稿不可选，历史订单继续按提交快照展示；单/多选、数量和价格增量由服务端校验。
- 新订单组可包含多个产品子订单；每个子订单独立走现有业务事实链，历史订单非破坏性回填为一组一子单。
- 动态值支持 string、number、boolean、array、object 和 quantity；后端按冻结的 schema version 校验。
- 未配置正式价格时返回“待报价”；已报价订单保存版本化配置和价格快照，人工改价必须有原因和审计。
- 单文件上限统一为 500MB；订单组共享资料和子订单专属资料分别挂载并执行服务端鉴权。
- 标准工时数据库/API/版本/审计底座保留；客户正式数据到位前管理端不展示菜单，版本保持空值/DRAFT/INACTIVE，默认运行时开关禁止发布、实例快照、截止时间/超时和绩效计算。正式启用后新实例冻结当时有效值，旧实例不受后续修改影响。
- 医生端可以在一个病例下添加至少两个普通产品，保存草稿、刷新、返回、继续和提交均不丢失且不重复创建。
- 隐形正畸 A 型由配置启用，数据结构支持多类型；方案版本、内审、医生确认、生产批次和阶段调整均为追加式可审计事实。
- D-173 对新链路持续有效：授权生产审核员主审、ADMIN 监控及有理由兜底、普通 WORKER/CS 禁止；正畸方案内审、医生确认和生产审核互不替代。
- 旧单产品 API 和历史页面在迁移期继续可用；医生端、WebSocket 和 AI 不返回内部工序、员工、工时、返工、绩效和责任分类。
- 目标后端测试、OpenAPI 检查、前端 typecheck/build、专项脚本、`git diff --check`、项目 acceptance 和真实浏览器全链均通过；Task 8 仍为 `NOT_READY`。
