## Summary

2026-08-02 客户对演示环境完成一轮验收，标记 CHK003 / CHK006 / CHK008 / CHK012 / CHK014 五条「⚠️ 部分满足」。

逐条核查后确认：**没有一条属于二期**。二期基线（`docs/acceptance/phase-two-scope-baseline-20260726.md`）只跟 M2 / M3 / M6，并明确写了「设备、物料、安环、成本和奖惩保留一期现状，不计入二期验收」。这五条全部落在三类里：**一期范围内未做**、**一期确认时被延后**、**一期新增小需求**。

核查过程中另外发现两个客户尚未提出的问题（P1 / P2），其中 P1 是真缺陷：`complaint_rate` / `return_rate` 在后端被写死为 `0.0`，属于 `docs/development/status-vocabulary.md` 点名的那类「不抛错，只让数据悄悄不正确」的缺陷。

本 Goal 与 `GOAL-033 / TASK-034` **并行、不合并**——TASK-034 的 Non-goals 明确排除了统计口径与既有业务语义改动，混入会搅浑其 A 批次的越权测试基线。

## Scope

- G1：前端展示欠账（周环比接线、部门表补上月对照、独立本月 / 上月对比图）。
- G2：指标真实化（客诉率接真实事实表、退货率显式置空、Top10 带上月对照）。
- G3：AI 能力增强（AI-6 牙科 FAQ、AI-7 智能推荐产品，走真实 DeepSeek）。
- G4：客服端设置落地（客户分配、常用回复），依赖 TASK-034 A 批次。

## Non-goals

- 不做管理端角色 / 菜单 / 组织管理界面（TASK-034 C）。
- 不改 `WORKBENCH_DEPARTMENTS` 硬编码部门（并入 TASK-034 C 的组织管理）。
- 不做交期计算、试戴、过程确认、订单类型（TASK-034 F）。
- 不录入客户未提供的标准制作周期 / 价格 / 标准工时（CP 项）。
- 不为缺少可信口径的指标虚构基准值（如部门级完成达成率的上月值、部门级外返 / 客诉）。
- 不把 Task 8 改为 `READY`。

## Acceptance

- 客服工作台与生产工作台首屏不再出现「待接入」占位文案。
- 每个部门都能同时读到当天值与上月平均值。
- 客服工作台有独立的「本月 vs 上月」对比图。
- 十大客户排名每行带上月同口径对照。
- 全站不存在写死的统计常量；未启用的口径显示「口径未启用」，不显示 0%。
- FAQ 与智能推荐在真实 DeepSeek 环境下可用，且不突破 AI-3 医生端安全读边界。
- 客户分配与常用回复可实操，有越权拒绝测试。
- Task 8 保持 `NOT_READY`。

## Risks

- 客诉率把「客服登记的外返」等同于「客诉」是我方拟定口径，需登记待甲方确认。
- 退货率一期置空；若客户坚持要数值，需先在 TASK-034 F 引入「退货订单」类型。
- FAQ 语料属客户输入，先用我方拟定的牙科通用条目并标注「示例内容，待甲方确认」。
- G4 若抢在 TASK-034 A 之前做，`data_scope` 的 `ASSIGNED` 档要在用户级和角色级各写一遍，返工成本高于等待成本。
