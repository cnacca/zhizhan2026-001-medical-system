# 质量核验循环

## 目的

本流程把外部测试反馈转化为可复现、可修复、可回归和可交接的缺陷闭环。它适用于当前工作树中的缺陷核验与修复，不把旧版本的测试结论直接视为当前结论。

## 文档职责与读取顺序

新窗口处理缺陷时，按以下顺序读取：

1. 本文档：了解循环规则、验收门禁和停止条件。
2. `feedback-source-YYYY-MM-DD.md`：了解旧反馈的来源和完整范围。
3. `defect-tracker.md`：只选择一个 `OPEN` 或 `BLOCKED` 缺陷继续处理。
4. 该缺陷引用的 `evidence/YYYY-MM-DD/BUG-XXX.md`：复用已验证事实，不重猜根因。
5. 当前代码、脚本和运行环境：它们优先于任何历史文档。

`defect-tracker.md` 记录实时状态；来源记录不随修复结果改写；证据文件记录一次具体运行。

## 不可违反的边界

- 旧版测试报告是输入，不是当前版本的 FAIL 证据。
- 每项结论必须绑定当前工作树、分支、提交号和未提交改动摘要。
- 不通过隐藏入口、吞掉异常、放宽权限、删除断言或篡改验收文案取得 PASS。
- 任何医生端验证都不得暴露内部工序、员工、入检/出检、工时、返工、绩效或责任分类数据。
- 本地脚本、页面或演示数据通过，不等于真实环境、客户验收或 Task 8 完成。
- 不记录密码、Token、密钥、客户个人数据或未经脱敏的生产日志。

## 状态模型

每个 BUG 同时拥有一个生命周期和一个当前环节，二者不能互相替代。

| 字段 | 允许值 | 说明 |
| --- | --- | --- |
| 生命周期 | `OPEN`、`BLOCKED`、`CLOSED`、`NOT_APPLICABLE` | 是否仍需要工程动作。 |
| 当前环节 | `BASELINE`、`REPRODUCE`、`DIAGNOSE`、`PLAN`、`FIX`、`TARGET_VERIFY`、`REGRESSION`、`CLOSED` | 当前循环位置。 |
| 当前状态 | `待核验`、`已复现`、`已修复待回归`、`已关闭`、`不适用`、`阻塞` | 面向人的简明摘要。 |

初始状态必须是 `OPEN / BASELINE / 待核验`。只有满足本文“关闭门禁”后，才可写为 `CLOSED / CLOSED / 已关闭`。

## 循环阶段

| 环节 | 进入条件 | 必须记录 | 通过后 | 失败或不确定时 |
| --- | --- | --- | --- | --- |
| `BASELINE` | 已有 BUG 编号和来源记录 | 工作树、分支、提交号、未提交改动、服务地址、数据/账号前提 | `REPRODUCE` | 环境不可用则 `BLOCKED` |
| `REPRODUCE` | 基线已固定 | 可复制步骤、命令或页面路径、接口状态、最终路由/页面结果 | 出现同一行为则 `DIAGNOSE`，状态改为 `已复现` | 二次独立核验后再判 `NOT_APPLICABLE` 或 `BLOCKED` |
| `DIAGNOSE` | 已复现，或有足够反证说明行为变化 | 代码/配置/权限/数据/范围分类，最小证据和影响范围 | `PLAN` | 证据不足回到 `REPRODUCE` |
| `PLAN` | 根因和影响范围可解释 | 最小修复、非目标、定向验证、关联回归、范围决定 | `FIX` | 产品范围未定则 `BLOCKED` |
| `FIX` | 修复计划已确定 | 修改文件、测试变更和不变约束 | `TARGET_VERIFY` | 新现象或测试失败回到 `DIAGNOSE` |
| `TARGET_VERIFY` | 已完成最小修复 | 每条缺陷级通过条件、命令/接口/页面证据 | `REGRESSION` | 任一条件失败回到 `DIAGNOSE` |
| `REGRESSION` | 定向验证已通过 | 受影响端、关联接口和主链路结果 | `CLOSED` | 修复引入回归则回到 `FIX` |
| `CLOSED` | 所有关闭门禁满足 | 根因、修复文件、证据链接、剩余风险 | 生命周期改为 `CLOSED` | 不适用 |

## 验收标准

### 核验前置条件

每次运行证据必须包含：工作树绝对路径、分支、提交号、`git status --short` 摘要、启动方式、服务地址和与旧测试环境的差异。缺少其中任一项时，不得用该运行结果关闭 BUG。

### 通用 PASS / FAIL

- `PASS`：该环节的全部明确条件满足，并有可定位的当前证据。
- `FAIL`：任一明确条件不满足。
- `BLOCKED`：缺少环境、账号、外部服务或产品决定，且写明解除条件。
- `NOT_APPLICABLE`：当前功能经可定位的范围/产品依据确认不属于一期范围；“待接入”“演示中”或“暂不处理”不构成依据。

页面可打开、构建通过或接口不崩溃，均不能单独构成 PASS。

### 缺陷关闭门禁

一个 BUG 只有同时满足以下条件才可关闭：

1. 当前基线已重新核验，且已记录复现或反证。
2. 根因已归类并有证据支撑。
3. 已完成最小必要修复，或有产品范围依据支持 `NOT_APPLICABLE`。
4. 定向验证通过。
5. 关联回归通过。
6. 已写明修复文件、验证命令/页面路径、结果和剩余风险。
7. 没有降低权限、数据隔离、真实验收边界或 Task 8 状态来换取通过。

### 本轮缺陷级通过条件

| BUG | 必须满足的通过条件 |
| --- | --- |
| BUG-002 | 医生从管理端入口被拒绝；页面显示明确角色不匹配提示；不产生可用登录态；不跳转至任何工作台；四端正确入口登录仍通过；医生无法读取管理/生产内部数据。 |
| BUG-004 | 管理端绩效统计默认加载不返回 `400`；默认参数合法；有数据展示结果、无数据展示正常空态；合法筛选可用；相邻统计与派工路径回归通过。 |
| BUG-001 | 范围基线检查退出码为 `0`；`acceptance.json`、范围文档和检查规则对 C 类能力一致；修复不靠删除断言、降低要求或回退阶段指针；不改变 Task 8 的真实状态。 |
| BUG-003 | 每个反馈菜单均有唯一结论：已实现并验证、范围内未完成、经确认不属于一期范围，或独立的权限/接口缺陷；演示/待接入页面不得被标记为正式完成。 |

## 阻塞与升级

- 同一复现路径连续两次因环境问题无法执行：标记 `BLOCKED`，写明所缺服务、账号或数据，以及恢复后从哪个环节继续。
- 复现结果与旧反馈不同：先做第二次独立核验；仍不同则记录差异，不能猜测“已修复”。
- 产品范围决定影响 BUG-003 或关闭条件：停止实现，标记 `BLOCKED`，在台账中列出需要产品确认的菜单和问题。
- 一次修复导致关联回归失败：撤回“已修复待回归”结论，回到 `FIX`；若根因假设失效则回到 `DIAGNOSE`。
