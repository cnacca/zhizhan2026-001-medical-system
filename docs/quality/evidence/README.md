# 核验证据约定

## 目录和命名

每次实际核验建立一个日期目录：

```text
docs/quality/evidence/YYYY-MM-DD/BUG-XXX.md
```

同一 BUG 同一天有多次独立运行时，使用 `BUG-XXX-02.md`、`BUG-XXX-03.md`。证据文件一经引用，不覆盖历史结果；新的运行建立新文件。

## 最小证据模板

````md

- 日期：
- 工作树：
- 分支：
- 提交：
- 未提交改动摘要：
- 当前环节：
- 服务与环境差异：

1.

```text
命令、HTTP 状态码、最终路由或必要日志摘要
```

## 结果

- 判定：PASS / FAIL / BLOCKED / NOT_APPLICABLE
- 观察到的行为：
- 与旧反馈的关系：一致 / 不一致 / 无法比较
- 下一动作：

## 附件

- 截图或外部日志路径：
````

## 内容限制

- 不写入密码、Token、Cookie、密钥、数据库连接串、客户个人信息或未脱敏生产数据。
- 命令输出只保留支持结论的最小片段；完整大日志保留在本地运行目录时，台账仅记录路径和摘要。
- 截图只在页面行为、路由或视觉提示是关键证据时保存；截图路径必须可从仓库或明确的本地证据位置定位。

## 台账链接规则

每次 BUG 生命周期、当前环节或结论变化，都要在 `defect-tracker.md` 的“证据”字段新增对应文件链接。未链接证据的状态变化无效。
