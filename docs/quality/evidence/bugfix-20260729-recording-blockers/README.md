## 5. 修复说明

### 5.1 生产审核与生产池权限拆分

- 生产审核固定为 `ADMIN` 管理职责。
- `CS` 与 `WORKER` 的 `workflow:review-production` 角色权限和生产审核菜单由 V55 移除。
- 待生产审核订单只对管理员开放。
- 管理员审核并创建工序后，生产人员仍可按既有规则读取“未分配 READY 生产池”，不会破坏审核后的接单流程。
- 即使旧 Token 仍带生产审核权限码，非管理员服务端也会拒绝审核和待审核队列读取。

### 5.2 BUG-012 服务端 STL 门禁

- 非草稿创建和草稿提交都必须绑定至少一份有效 STL。
- 文件必须为当前医生所有、医生可见、`ACTIVE`、上传状态 `COMPLETED`，且文件名以 `.stl` 结尾。
- 空附件和仅 PDF 的提交均由后端返回 HTTP 400；草稿保存仍允许暂时没有 STL。

### 5.3 BUG-013 防重复草稿

- `saveWizardDraft()` 和 `nextWizardStep()` 增加同步重入保护。
- 保存、上传或提交期间，保存草稿、上一步、下一步按钮统一禁用。
- 真实浏览器对“下一步”并发三连点后只进入第 2 步，数据库只保留 1 张对应草稿。

### 5.4 医生与管理端消息

- 医生端加载订单后并行读取该医生合法可见的订单消息，生成真实会话，不再固定返回空数组。
- 会话使用患者档案真实姓名，不再退化为“患者 ID”。
- 管理端左侧会话只来源于真实待审消息，患者、订单、诊所、产品、发送方均可搜索。

## 9. 录屏与交付判断

**本轮 6 项录屏阻塞缺陷已关闭，可以重新录制这部分业务主链。**

建议录屏顺序：

1. 医生建立/选择患者，选择真实产品、牙位、材料并上传 STL。
2. 演示无 STL 无法继续，以及快速连点不会生成重复草稿。
3. 客服初审后切到生产端，展示 0 单。
4. 管理端生产审核通过后再切生产端，展示订单出现。
5. 生产端发送医生消息，管理端患者搜索和待办 1 条。
6. 管理端审核后待办归零，医生消息中心展示消息。

本结论不覆盖原报告中的生产 Nginx 代理配置、正式部署、真实客户数据、客户签字和 Task 8 上线 readiness。
