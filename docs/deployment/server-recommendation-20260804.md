# 服务器采购建议（给客户）

状态：ACTIVE / 2026-08-04
配套：`go-live-plan-20260804.md` §0.6、`customer-confirmation-checklist-20260804.md`

## 客户最新反馈

1. 现有三台云服务器上**对接了两个平台，但都没有大面积使用**；若部署本系统，客户愿意停掉其中一个。
2. 客户**不知道怎么升级**服务器。
3. 客户**不确定选哪个地区**，因为要求是「**国内能用，国外也能用**」。

## 结论先行

| 问题 | 结论 |
| --- | --- |
| 停掉一个平台能腾出资源吗 | **不能解决问题。** 现有三台都是 2 核 2 GB，停掉平台后仍是 2 核 2 GB，跑不动本系统 |
| 能把现有机器升级到够用吗 | 配置能升，**但地区改不了**——见下 |
| 选哪个地区 | **中国香港**。这是「国内国外都要用」唯一合理的单点选择 |
| 买什么配置 | **4 核 8 GB**，系统盘 ≥ 60 GB，带宽 ≥ 10 Mbps；**文件另存 COS** |
| 现有三台怎么办 | 与本系统无关，客户按自己业务需要处理 |

## 一、一个必须先讲清楚的限制：地区不能改

腾讯云官方文档明确：**轻量应用服务器创建成功后不支持更换地域**；
套餐只能**升级不能降级**，且是整套餐升级（不能单独加内存）。

这意味着：

- 客户现有的新加坡 / 硅谷 / 法兰克福三台，**无论怎么升级都还在原地区**；
- 想要香港的机器，**只能新购，不叫「升级」**。

这一条要先跟客户说明白，否则他会以为「升个级就行」，实际操作时会卡住。

## 二、为什么推荐中国香港

客户的要求是「国内能用，国外也能用」。这是个单点服务器要同时照顾两头的问题，
关键在于**谁是重度用户**：

| 用户 | 使用强度 | 说明 |
| --- | --- | --- |
| 工厂内部（客服 / 生产 / 管理） | **重度，每天 8 小时** | 一直在系统里操作订单、派工、质检 |
| 医生（国内 + 国外） | 中低频 | 下单、看进度、确认设计稿 |

**所以优先保证工厂那一头的体验。** 各地区到中国大陆的网络距离（一般经验值，实际以实测为准）：

| 地区 | 到中国大陆 | 到北美/欧洲 | 备案 |
| --- | --- | --- | --- |
| **中国香港** | **最近** | 中等 | **免备案** |
| 新加坡 | 中等 | 中等 | 免备案 |
| 硅谷 / 法兰克福 | 远 | 近（各自区域） | 免备案 |
| 中国大陆 | 最近 | 远 | **需备案，办理周期以周计** |

**香港是唯一同时满足「大陆访问快」+「免备案」+「国际出口好」的选择。**
香港本身是国际互联网枢纽，出海方向的质量优于大陆机房。

### 如果医生主要在欧美，怎么补

应用服务器仍放香港，另外两件事把海外体验拉起来：

1. **文件走对象存储 COS，并开启全球加速**——口扫 STL 是前端直传，
   不经过应用服务器，医生浏览器直接连 COS 就近节点。
2. **前端静态资源挂 CDN**——首屏 JS/CSS 由离用户最近的节点分发。

这样应用服务器只承担 API 请求（每次几 KB），跨境延迟的影响就小得多。

## 三、推荐配置

### 应用服务器（新购 1 台）

| 项 | 推荐 | 理由 |
| --- | --- | --- |
| 地域 | **中国香港** | 见上 |
| 镜像 | **Ubuntu 24.04 LTS** | 与现有三台一致，团队熟悉 |
| CPU / 内存 | **4 核 8 GB** | 最低需求约 5–6 GB（JVM ~2G + MySQL ~2G + Redis/nginx/系统 ~1G），8 GB 才有余量 |
| 系统盘 | **≥ 60 GB** | 文件走 COS 后，本地只存系统 + 镜像 + 数据库 |
| 带宽 | **≥ 10 Mbps** | 前端首屏约 3 MB（gzip 后约 700 KB）；若前端挂 CDN 可降到 5 Mbps |

**为什么 2 GB 一定不行**：后端 Java 进程和 MySQL 各自最低就要 2 GB 左右，
2 GB 总内存连一个都装不下，启动即 OOM。这不是调优能解决的。

### 对象存储 COS（新开）

| 项 | 说明 |
| --- | --- |
| 用途 | 存口扫 STL、病例照片、设计稿、账单 PDF |
| 容量 | **按量计费，不用预估**——这正是它替代 50 GB 系统盘的价值 |
| 地域 | 与应用服务器同地区或就近 |
| 加速 | 海外医生多的话开启全球加速 |

**注意**：本系统目前用 MinIO SDK。MinIO SDK 说的是 S3 协议，理论上可直连 COS，
但**已知坑是 COS 的桶名必须是 `<桶名>-<appid>` 格式**，否则返回 400。
这一条列为阶段一的头号验证事项，验证通过再让客户正式开通。

### 备份

工厂那台 32 GB / 7 TB 的 Windows 机器改作**异地备份目标**：
云上每日备份数据库与对象存储，回传到工厂机器保存。
机器不浪费，还正好补上「目前完全没有备份」这个缺口。

## 四、给客户的操作步骤

### 新购香港服务器

1. 登录腾讯云控制台 → 搜索「轻量应用服务器」
2. 点「新建」
3. **地域选「中国香港」**（这一步选错后面改不了）
4. 镜像选 **Ubuntu 24.04 LTS**
5. 套餐选 **4 核 8 GB**，留意套餐带的带宽与月流量
6. 设置 root 密码或上传 SSH 密钥
7. 购买完成后，把**公网 IP** 和**登录方式**给到我们

### 若客户仍想升级现有机器（不推荐，地区不对）

控制台 → 轻量应用服务器 → 选中实例 → 更多 → **升级套餐**。
注意只能升不能降，且**地域不变**。

## 六、一条建议

**不要把本系统和其他业务混跑在同一台机器上。** 客户提到会停掉一个平台腾位置，
但即使停掉，混跑仍有三个问题：资源互相抢占、一方故障影响另一方、备份与恢复互相牵制。
本系统单独一台机器，出问题时排查和回滚都干净得多。
