# DoctorCaseGroupWizard 像素复刻规格

## 基准

- 参考页面：`frontend/public/reference/doctor-portal.html` 中 `#mo-order`
- 参考截图：`docs/quality/doctor-portal-pixel-clone/screenshots/reference/new-order-1440x900.png`
- 目标文件：`frontend/src/doctor/DoctorCaseGroupWizard.vue`
- 交互模型：步骤点击与表单交互驱动；主体和左侧目录各自纵向滚动；页脚固定。
- 业务差异：保留当前真实目录、病例订单组、多产品子订单和待报价逻辑，不恢复参考页的演示价格或单产品限制。

## 页面拓扑

1. 56px 深蓝顶栏：左侧标题，右侧当前分类/步骤说明与 32px 关闭按钮。
2. 43px 浅灰步骤栏：步骤从左向右排列，18px 圆形编号，当前步骤蓝色下划线。
3. 主体：260px 左侧目录 + 可滚动主内容。
4. 60px 固定页脚：左侧上下文信息，右侧返回/继续按钮。

## 精确视觉值

### 设计变量

- 背景：`#ffffff`；浅灰：`#f7f9fc` / `#eef2f8`
- 主蓝：`#2563eb`；深蓝：`#1d4ed8`；海军蓝：`#0f2554`
- 正文：`#0f172a`；次正文：`#475569`；弱文字：`#94a3b8`
- 边框：`#e2e8f0` / `#cbd5e1`
- 正文：`Plus Jakarta Sans`；标题：`Lora`
- 通用圆角：8px；分类卡片 10px；输入框 8px。

### 顶栏

- 高 56px；背景 `#0f2554`；左右内边距 28px。
- 标题 15px/600，Lora；右侧说明 12px，白色 50% 透明度。
- 关闭按钮 32×32px、8px 圆角、白色 10% 背景。

### 步骤栏

- 高 43px；背景 `#f7f9fc`；底边框 1.5px `#e2e8f0`。
- 单步 padding `10px 16px 12px`；文字 11px/600。
- 编号 18×18px、9px/700；当前蓝底白字，完成态绿底白字。

### 左侧目录

- 宽 260px；背景 `#f7f9fc`；右边框 1.5px。
- 标题区 padding `14px 12px`。
- 分类列表单列，间距 7px；每卡片 2px 边框、10px 圆角、padding `12px 14px`、白底。
- 图标 22px；中文产品大类 12px/700；产品数量 10px。
- 具体产品使用 1.5px 边框、7px 圆角、padding `8px 12px`、11px/600。

### 主内容

- 容器 padding `24px 32px`；第一步内容最大宽度 800px，并在可用主区居中。
- 页面标题 18px/600 Lora；说明 13px，底部间距 20px。
- 医生信息条：蓝色浅底，1.5px 蓝边框，10px 圆角，padding `14px 18px`。
- 区块底部间距 22px；区块标题 11px/700、蓝色、大写/字距 0.5px、底边框 1.5px。
- 表单两列，列间距 14px；标签 10px/700；输入高约 38px，浅灰底、1.5px 边框、8px 圆角。
- 患者搜索默认只显示搜索框；聚焦/输入时出现下拉；选中后显示绿色患者摘要。
- 已选多产品清单只在存在子订单时显示，采用参考页价格/确认区的紧凑行样式。

### 页脚

- 高 60px；白底；上边框 1.5px；左右 padding 28px。
- 主按钮 padding `10px 28px`、9px 圆角、13px/600、蓝底白字。
- 初始未产生订单组时不显示“保存草稿”；已有草稿后在左侧显示。

## 状态与行为

- 分类卡片 hover：边框变浅蓝、背景 `#eff6ff`。
- 分类卡片 active：边框 `#3b82f6`、浅蓝背景、外圈 `0 0 0 3px rgba(59,130,246,.1)`。
- 患者搜索 focus：白底、浅蓝边框、3px 蓝色透明外圈。
- 产品点击：已有患者时创建真实子订单；已选产品保持选中态，允许继续选择其他分类产品。
- 清空/切换分类不删除已选产品；已选清单继续作为病例订单组摘要。

## 响应式

- 1440px / 1280px：保持 260px 左栏和最大 800px 主表单。
- 小于 900px：左栏变为横向可滚动目录，主内容单列；不隐藏步骤语义。
- 小于 640px：步骤文字允许横向滚动，主内容 padding 14px，双列表单改为单列。

## 不允许的偏差

- 不使用大号居中圆点进度条或连接线。
- 不把患者列表常驻成大卡片墙。
- 不把订单要求与患者拆成两个并排大卡片。
- 不把六个产品大类横排在主内容里。
- 不写入演示基础价、假工期、假患者或内部生产字段。

## 第二步牙位图

- 直接复刻参考 HTML 的 700×330 SVG 牙位图，不使用 emoji、字体图标或 32 个独立方形卡片代替。
- 上下颌各 16 颗牙，使用 FDI 编号；磨牙、前磨牙、犬牙、切牙分别使用对应牙冠宽度、牙根长度和根数。
- 图内保留上下颌标题、左右侧 R/L 标记、正中虚线、咬合参考线和 FDI 编号。
- 单击选择单牙，使用蓝色描边/浅蓝填充；同颌连续拖拽选择桥体，使用橙色描边/浅橙填充；再次单击取消。
- 活动修复、常规正畸和种植专项标记继续保留业务语义，但只能通过同一牙科 SVG 的颜色与图例表达，不改变牙体结构。
- 图表下方显示业务化选择摘要；未选时提示操作方法，不显示表字段名、内部枚举值或 JSON。

## 第三步材料与工艺

### 参考来源

- 视觉基准：`frontend/public/reference/doctor-portal.html` 的 `buildMaterial`、`buildImplantSpec`、`buildRemovableMat`。
- 业务基准：《动态下单表最终版.docx》正文“第三页”中的固定修复、种植修复、活动义齿、正畸产品和设计订单模板。
- 第三步是医生逐个配置已选产品的业务表单，不是产品配置中心，也不展示目录版本、绑定关系、Schema 或价格引擎信息。

### 页面结构

1. 左侧保持 260px 已选产品切换栏；每个病例产品独立显示完成状态，点击只切换当前配置对象。
2. 右侧内容宽度最大 800px，核心表单宽度最大 780px；当前产品名称、类别和产品规格使用一行紧凑摘要，不展示内部产品订单号。
3. 每个业务分组使用参考页 `.mo-section` 结构：底部间距 22px；标题 11px/700、蓝色、字距 0.5px；标题下方 1.5px 浅蓝分隔线。
4. 表单使用两列网格，列/行间距 14px；通栏备注跨两列。标签 10px/700；输入框约 38px 高、浅灰底、1.5px 边框、8px 圆角；聚焦后白底、蓝边和 3px 浅蓝外圈。
5. 小于 640px 时改成单列，通栏字段恢复单列；产品切换栏在小于 900px 时改为横向滚动。

### 数据与交互

- 主材料/制作项目必须是单选下拉；选项来自当前具体产品适用的已发布配置，客户资料常量只作为迁移期兜底。不得同时再展示一组含义相同的材料复选框。
- 后端材料绑定中 `SINGLE` 组使用下拉；只有明确为 `MULTIPLE` 的附加材料才使用复选，并在选中后显示数量。
- 配件单独置于“附加选项”分组；数量只在选中后显示。产品变体仅在当前产品确有变体时出现。
- 选择牙色系统后条件显示牙色值；选择颈/体/切端分色后显示三个独立色号下拉。
- 切换病例产品不丢失已填值；保存只保存当前产品；错误提示定位到当前业务分组。

### 分类专属模板

- 固定修复：主材料/制作项目、产品规格（如有）、边缘类型、牙色系统/牙色或三区分色、抛光程度、颜色与材料备注、适用的精密附件。
- 种植修复：先显示种植参数（种植系统、直径/长度、连接、固位、基台、螺丝开口），再显示修复材料和牙色；基台/桥架仅在适用产品显示。
- 活动义齿：主材料/制作项目、卡环设计、义齿牙品牌、牙色系统/牙色、基托颜色、抛光和备注；不显示“牙龈仿生色”选项。
- 常规正畸：当前正畸产品、产品规格（如有）和正畸附件；附件为多选并记录数量/位置说明。
- 设计服务：当前设计服务、交付文件格式和 6/12/24/48 小时交期。
- 隐形正畸保持专项配置入口，不套用普通材料模板。

### 医生端文案

- 分组名称使用“材料与工艺、种植参数、修复材料、附加选项、补充要求”等业务语言。
- 不显示“客户资料列出的、未提供价格、发布配置、绑定、后台校验、自由文本策略”等实现或研发说明。
- 未配置正式价格时只显示“待报价”，不得展示演示价、基础价或 Warranty 等客户未确认字段。

## 医生端文案边界

- 医生界面只展示患者、产品、牙位、材料、资料、试戴、报价、交期和订单进度等业务语言。
- 不向医生展示“后端、接口、数据库、发布目录、配置中心、配置快照、Schema、校验冻结、SKU、订单组/子订单”等实现口径。
- 病例下多产品统一称“病例订单”和“产品订单”；技术上仍保持订单组与子订单模型，不改接口和数据事实。
- 暂不可用能力统一提示“暂未开放”或“请联系订单支持”，不把开发进度或后端接入状态暴露给医生。
- 报价仍为“待报价”，但不解释演示价、基础价或服务端计价实现。
