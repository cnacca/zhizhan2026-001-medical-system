# Phase One Frontend Task Scope

更新日期：2026-07-04

## 用途

本文档用于后续前端开发接手：把四个端口已经出现的入口拆成一期开发任务、已完成第一增量、演示增强和超过一期范围四类，避免后续只因为左侧栏有入口就继续扩散范围。

一期前端开发仍以 `PROJECT.md` 的 P0 主业务链路、`docs/acceptance/task-8-acceptance-matrix.md` 的 12 步验收链路、`docs/deployment/readiness-checklist.md` 的上线缺口为准。`frontend/src/App.vue` 中的 `displayNavigationConfig` 是四端左侧栏与工作台入口来源，`accountNavigationConfig` 是账号弹窗入口来源，但导航存在不等于一期完成。

## 状态口径

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| DONE | 已接真实接口或已有明确浏览器/自动化验收证据。 | 保留，不重写；只在 12 步主链路或验收缺口暴露问题时补小修。 |
| FIRST_INCREMENT | 已有页面、接口或只读汇总，但仍缺完整业务闭环。 | 可列入一期任务，但任务必须写清剩余验收，不得直接标正式完成。 |
| TODO_PHASE_ONE | 一期必须做，但当前只有占位、演示入口或路径不完整。 | 优先拆成可验收小任务。 |
| SHOWCASE_ONLY | 客户演示或经营看板增强，不属于 P0 主链路硬阻塞。 | 可以保留入口和只读汇总，不扩成完整 CRUD/审批/配置，除非客户/PM 明确确认。 |
| DEFER_PHASE_TWO | 超过一期范围或当前资料未确认。 | 不作为一期验收阻塞；如入口已存在，保持中文占位或移到后续 backlog。 |

## 已完成内容怎么处理

- 已完成并接入真实接口的能力保留为一期基础，不回滚、不重写，后续只补验收缺口。
- 已完成但标为 FIRST_INCREMENT 的能力，不能在汇报中说“正式完成”，只能说“第一增量已完成，仍缺某某验收”。
- 9D.49 到 9D.54 的质量、设备、物料、安环、成本、奖惩真实汇总属于展示增强的第一增量，可用于客户演示，但不自动升级为完整一期业务闭环。
- 9D.36 的四端视觉、导航、工作台、账号面板属于前端体验基线，后续开发必须沿用，不要为了新任务把端口主题、中文业务语言和侧栏结构打散。

## 多余或超过一期内容怎么处理

| 内容 | 当前处理 |
| --- | --- |
| 外协管理、外协成本 | 归入二期或客户确认后的扩展范围；一期只保留演示入口或成本汇总中的只读字段。 |
| 云端数据中心 | 不做独立模块；一期文件能力收敛到订单附件、设计稿、终检附件和权限签名 URL。 |
| 设备/物料/安环完整 CRUD | 不进一期；当前只读汇总可保留，录入、审批、采集、联动后置。 |
| 成本核算、奖惩审批、绩效申诉 | 不作为一期硬验收；一期只保留统计/汇总和绩效基础。 |
| AI 治理完整后台 | 不扩成完整运营平台；一期只保留必要治理、审计、预算和安全防护第一增量。 |
| 完整账号偏好、通知偏好、多设备会话 UI | 不作为一期主链路；正式鉴权策略和基础安全优先。 |
| 工序链拖拽编辑、物流平台自动同步、AI 自动审核/发送 | `PROJECT.md` 已明确一期不做，后续开发不得误纳入一期。 |

## 推荐后续前端任务顺序

1. 返工影响图形化第一增量：补生产端返工处理与后续工序影响的可读图形，不做复杂甘特和拖拽排产。
2. 客服协同闭环：补消息审核、设计稿审核、账单管理、配送管理和 AI 翻译确认写入生产指令。
3. 12 步主链路浏览器 smoke：用固定演示数据跑完四端真实路径，沉淀客户验收证据。
4. 文件与设计稿体验：补真实弱网/跨设备上传、设计稿预览 URL 聚合、终检附件预览边界。
5. 绩效与管理侧收口：补绩效周期筛选、标准工时配置、完整公式和管理侧汇总。
