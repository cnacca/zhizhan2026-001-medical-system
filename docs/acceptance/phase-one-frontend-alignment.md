## 判定规则

| 状态 | 含义 |
| --- | --- |
| MATCHED | 前端已有页面入口，且接入真实接口或已有浏览器 smoke / 自动化证据。 |
| PARTIAL | 前端已有入口或只读汇总，但仍是第一增量，缺完整编辑、审批、附件、图形化、真实场景验收等。 |
| PLACEHOLDER | 前端导航已有演示入口，但当前主要是占位说明，尚未接入正式接口和完整权限。 |
| GAP | 一期必需能力当前前端没有形成可验收用户路径。 |

## 按端口检查

### 医生端

匹配度最高。医生端已覆盖一期核心可见路径：新建订单、我的订单、设计稿确认、账单物流、沟通留言、订单助手、通知中心。

主要不匹配点：

- 医生端不保留独立 `医生文件资料` / `/doctor/files` 入口；病例、口扫、图片、处方和设计稿文件归入医生订单链路。
- 上传能力在订单页内完成，仍不是完整文件管理页面。
- 设计稿可见且已补预览 URL 聚合与 9D.62.3 确认数据动作，但仍缺多轮驳回/重传完整验收。

### 客服端

客服端已覆盖初审第一增量，但距离一期完整客服中台仍有明显差距。

已匹配：

- 待审核订单和全部订单入口。
- 内部订单页可处理客服初审和设计稿上传第一增量。
- 通知中心可用。

主要不匹配点：

- 沟通中心、客户管理、待审核消息、设计稿管理、账单管理已具备多个第一增量；配送管理已由 9D.91 接入 `/delivery` 人工异常跟进第一增量；外协管理仍为占位。
- AI 翻译、客服查询助手、生产备注助手仍是导航或后端能力，没有形成完整客服页面工作流。

### 生产端

生产端已经能演示生产主链路，但多数经营/现场管理模块仍是只读汇总或演示入口。

已匹配：

- 生产看板、我的任务、入检/出检、工时、返工终检、绩效统计。
- 质量、设备、物料、安环、成本、奖惩已有真实后端汇总接口第一增量。

主要不匹配点：

- 工作单、扫码登记、员工管理、消息中心、云端数据中心仍是占位。
- 质量/设备/物料/安环/成本/奖惩目前以只读汇总为主，缺录入、编辑、审批、附件和完整 CRUD。
- 真实电子签章/复杂报告模板、完整终检页面和返工完整浏览器链路是一期生产端关键缺口。

### 管理端

管理端当前偏“最小管理入口 + 演示导航”，还不是完整 RuoYi 管理后台。

已匹配：

- 动态表单管理。
- 返工字典管理。
- 工序进度、派工、绩效统计、通知审计入口。

主要不匹配点：

- 用户管理、角色权限、部门岗位、设备、物料、外协、账单配送、AI 治理多为占位或非完整管理页；客户诊所已由 9D.85 接真实接口，人员档案 / 工作量已由 9D.86 接真实接口，质量记录 / 外返登记已由 9D.87 接真实接口，客服协同可见性 smoke 已由 9D.88 补订单上下文和驳回通知证据，医生账户设置已由 9D.89 接真实接口，产品参数 / 价格体系一期最小后台已由 9D.90 接真实接口，客服配送管理已由 9D.91 接 `/delivery` 人工异常跟进第一增量。
- 完整 RuoYi 管理 UI、操作日志、通用 DataScope UI 仍未完成；9D.75 只完成后端生产权限码优先模式第一段。

## 前端下一步优先级

为了服务「完成一期」而不是继续扩散页面，前端下一步建议按这个顺序补：

1. 设备 / 物料 / 安环 / 成本 / 奖惩一期闭环拆解第一增量：先把五类模块按 PRD V2.0 拆成录入、编辑、审批 / 处理状态、趋势和验收命令，避免继续只停留在只读汇总。
2. 医生提交前 AI-4 资料缺失自动触发体验：补下单提交前缺失检查提示和确认路径，不接新外部服务。
3. 客服订单管理按 PRD 字段筛选 / 订单详情 smoke：补更贴近 PRD 的筛选和详情可见性验收。
