一期完成口径以 `PROJECT.md` 的 P0 主业务链路、`docs/acceptance/task-8-acceptance-matrix.md` 的 12 步主链路、`docs/deployment/readiness-checklist.md` 的上线缺口为准。Task 8 / 9D 小任务只是补齐一期上线缺口的执行拆分。

当前结论：前端已经能支撑一期主链路的演示版和多段真实接口第一增量，但还没有达到一期正式交付。9D.58 已补客服协同台消息审核第一增量；9D.59 已补客服资料缺失提示与 AI 翻译草稿确认第一增量；9D.60 已补医生端设计稿预览 URL 聚合第一增量；9D.61 已补账单文件绑定和医生端账单预览第一增量；9D.62 已固定 12 步主链路浏览器 smoke 第一增量入口。主要差距仍集中在 12 步主链路真实业务数据闭环、终检 PDF/签名、绩效完整闭环、真实弱网/跨设备上传、生产级通知与部署验收。

后续按端口拆任务、判断已完成内容和处理超过一期范围的入口时，使用 `docs/acceptance/phase-one-frontend-task-scope.md`。

## 判定规则

| 状态 | 含义 |
| --- | --- |
| MATCHED | 前端已有页面入口，且接入真实接口或已有浏览器 smoke / 自动化证据。 |
| PARTIAL | 前端已有入口或只读汇总，但仍是第一增量，缺完整编辑、审批、附件、图形化、真实场景验收等。 |
| PLACEHOLDER | 前端导航已有演示入口，但当前主要是占位说明，尚未接入正式接口和完整权限。 |
| GAP | 一期必需能力当前前端没有形成可验收用户路径。 |

## 按端口检查

### 医生端

匹配度最高。医生端已覆盖一期核心可见路径：新建订单、我的订单、设计稿确认、账单物流、沟通留言、订单助手、通知中心。

主要不匹配点：

- `医生文件资料` 当前仍是演示入口，不是独立文件资料中心。
- 上传能力在订单页内完成，仍不是完整文件管理页面。
- 设计稿可见但缺预览 URL 聚合和多轮驳回/重传完整验收。

### 客服端

客服端已覆盖初审第一增量，但距离一期完整客服中台仍有明显差距。

已匹配：

- 待审核订单和全部订单入口。
- 内部订单页可处理客服初审和设计稿上传第一增量。
- 通知中心可用。

主要不匹配点：

- 沟通中心、客户管理、待审核消息、设计稿管理、账单管理、配送管理、外协管理多为占位。
- AI 翻译、客服查询助手、生产备注助手仍是导航或后端能力，没有形成完整客服页面工作流。

### 生产端

生产端已经能演示生产主链路，但多数经营/现场管理模块仍是只读汇总或演示入口。

已匹配：

- 生产看板、我的任务、入检/出检、工时、返工终检、绩效统计。
- 质量、设备、物料、安环、成本、奖惩已有真实后端汇总接口第一增量。

主要不匹配点：

- 工作单、扫码登记、员工管理、消息中心、云端数据中心仍是占位。
- 质量/设备/物料/安环/成本/奖惩目前以只读汇总为主，缺录入、编辑、审批、附件和完整 CRUD。
- 终检 PDF/签名、完整终检页面和返工完整浏览器链路是一期生产端关键缺口。

### 管理端

管理端当前偏“最小管理入口 + 演示导航”，还不是完整 RuoYi 管理后台。

已匹配：

- 动态表单管理。
- 返工字典管理。
- 工序进度、派工、绩效统计、通知审计入口。

主要不匹配点：

- 用户管理、角色权限、部门岗位、客户诊所、人员、设备、物料、外协、账单配送、AI 治理多为占位或非完整管理页。
- 完整 RuoYi 管理 UI、操作日志、通用 DataScope UI 仍未完成。

## 前端下一步优先级

为了服务「完成一期」而不是继续扩散页面，前端下一步建议按这个顺序补：

1. 12 步主链路浏览器 smoke：用固定演示数据把医生下单到确认收货跑通，形成客户验收证据。
2. 客服端设计稿审核预览增强：在 9D.60 医生端预览基础上，补客服审核侧预览体验。
3. 绩效周期筛选：补生产管理侧可解释性和绩效验收。
4. 真实弱网/跨设备上传与文件预览验收：补文件体验和上线验收。
