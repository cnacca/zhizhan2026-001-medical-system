> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-17
> 权威视觉参考：`frontend/public/reference/cs-portal.html`
> 参考文件 SHA-256：`035c43e735fe73badbcc0612e176c4a974057c2d1418470b0c72ac089a7f304d`

## 1. 设计结论

客服端左侧栏采用“参考客服端的扁平分组结构 + 当前项目已确认业务补充”。菜单分组只承担视觉归类，不作为可点击、可展开的父级菜单。所有菜单项直接进入对应页面，待审核、全部、待处理等状态统一放进页面内部的快捷筛选。

不能完全照搬参考 HTML 的七个页面：当前项目已经确认客服端包含订单、沟通、客户、产品、配送、账单和外协等业务模块；产品管理和外协管理没有直接参考页面，账单与配送在参考页中合并、在当前项目中则继续作为两个独立入口。

## 3. 视觉规格

| 项目 | 确认值 |
| --- | --- |
| 侧栏宽度 | `236px`，固定定位，`min-height: 100vh` |
| 侧栏背景 | `#1e1b4b`，保留参考页斜线纹理 |
| 侧栏阴影 | `4px 0 24px rgba(30,27,75,.22)` |
| 品牌区 | `97px`，底部 `1px` 半透明分隔线 |
| 账号区 | `57px`，头像 `32×32px` |
| 分组标题 | `9px`，半透明白色，作为不可点击的视觉标签 |
| 菜单项 | `220×33.5px`，圆角 `7px`，字号 `12px` |
| 激活状态 | 半透明白色背景，左侧内描边 `3px #a78bfa` |
| 图标 | 槽位宽 `15px`、图标字号约 `13px`；保留参考符号语义，扩展页面使用同尺寸 Emoji 或内联 SVG |
| Badge | 只显示真实待处理数量，不使用静态装饰数字 |

正式系统不保留参考原型的演示账号切换。点击左侧栏账号区后，客服经理进入“设置与账号”，其他岗位进入个人常用回复和通知偏好；退出登录使用真实认证流程。正常菜单只显示中文业务名称，不向客户展示 route、permission、component 或英文角色码。

帮助中心不放在左侧栏。顶栏问号是唯一帮助入口：点击后先打开当前页面帮助抽屉，再由抽屉进入完整帮助中心。侧栏底部只保留客服端版本信息。

全部端内页面使用同一顶栏顺序：“当前页面 / 搜索 / 数据时间 / 通知 / 帮助 / ＋ 新建订单”。顶栏不重复显示当前账号，账号信息保留在左侧栏账号区。“＋ 新建订单”只确定按钮入口且不附带数量；本次不调整该功能内部页面和后续业务流程。

## 6. 信息审核/翻译的职责边界

“信息审核/翻译”不是对原“资料处理”的简单改名。它继续使用 `page-datacenter` 的视觉和交互作为参考，但业务范围收窄为翻译人员负责的文字信息处理。

### 6.1 页面负责

1. 查看客户提交的原始文字要求；
2. 判断内容是否清楚、是否矛盾、是否需要翻译；
3. 完成外文翻译和专业术语校对；
4. 将零散要求整理成结构化生产备注；
5. 标记信息疑点并提交给客服发起问单；
6. 保存原文、翻译稿、最终确认稿、版本和处理记录。

### 6.2 页面不负责

| 非本页职责 | 正确去向 |
| --- | --- |
| 新订单进入平台并完成客服登记 | 订单管理，使用“新订单 / 登记订单 / 已登记”口径 |
| 缺少照片、口扫、处方等附件 | 信息审核/翻译识别和标记；需联系客户时提交问单沟通 |
| 判断订单是否满足生产条件 | 生产端专业审核，客服不审单 |
| 联系客户补资料或确认要求 | 问单沟通，由客服负责 |
| 对外设计确认和修改意见沟通 | 问单沟通 |
| 生产数据是否满足实际生产 | 生产端数据审核 |

### 6.3 角色权限

| 角色 | 信息审核/翻译页面权限 |
| --- | --- |
| 翻译人员 | 可进入、领取或处理任务、保存翻译稿、提交最终稿、标记疑点 |
| 普通客服 | 默认不显示该菜单，不参与翻译和信息整理 |
| 客服经理 | 可查看进度和结果，默认不直接修改翻译内容 |

菜单隐藏不能代替权限控制；列表、详情、保存、提交、导出等接口都必须使用相同角色与数据范围校验。

## 7. 设计稿管理与设计确认职责边界

“设计稿管理”和“设计确认”不是同一个功能：

| 能力 | 所属页面 |
| --- | --- |
| 查看设计文件 | 设计稿管理 |
| 查看和修订产品、色号、牙位、客户指示 | 设计稿管理 |
| 添加设计稿版本 | 设计稿管理 |
| 客服内部审核设计稿 | 设计稿管理 |
| 发起设计确认 | 设计稿管理中的触发按钮 |
| 向客户发送设计稿 | 问单沟通 |
| 客户确认、驳回或提出修改意见 | 问单沟通 |
| 围绕设计稿继续沟通 | 问单沟通 |
| 查看确认结果和版本状态 | 两个页面同步展示 |

设计稿管理中的“审核通过并发起设计确认”会创建一条设计确认问单。对外确认在问单沟通中完成，结果自动回写设计稿版本状态。不得再建立独立的“设计确认”菜单或页面。

## 8. 工作流关系

```text
客户提交订单
      ↓
客服：新订单登记
确认订单进入平台并记录登记人/登记时间，不执行客服审单
      ↓
翻译：信息审核/翻译
检查资料与客户指示、翻译、校对、整理生产备注、标记疑点
      ↓
存在疑点 ──────────────┐
      ↓                 │
客服：问单沟通          │
向客户确认并回传结果 ───┘
      ↓
翻译完成最终稿
      ↓
进入生产审核
```

## 9. 与工作台确认稿的关系

本次客户反馈只调整菜单名称、页面职责和角色权限。已确认的工作台指标保持不变：工作台继续分别展示“信息评审”和“翻译待审”，不因菜单合并而改动工作台卡片数量或布局。

## 10. 实施边界

- 菜单与职责方案已经冻结，当前按参考 HTML 执行前端像素校准；
- 未完成后端岗位、权限和数据范围继续作为后续缺口，不用前端显示结果冒充完成；
- 设计稿管理保留独立页面；设计确认只作为问单类型，不建立独立页面；
- 产品管理和外协管理没有一比一参考页面，必须单独完成页面结构确认；
- 账单与配送继续保留两个入口，不能未经新确认改为一个页面；
- 角色权限必须由后端同步限制，不能只依赖前端隐藏菜单；
- 实施后需覆盖客服、翻译人员和客服经理的菜单、页面与数据范围对比。
