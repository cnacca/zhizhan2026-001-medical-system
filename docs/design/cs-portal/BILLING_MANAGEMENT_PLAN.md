# 客服端账单管理页面重构确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-18
> 权威视觉参考：`frontend/public/reference/cs-portal.html`、`frontend/public/reference/doctor-portal.html`

## 1. 设计结论

账单管理定位为订单账单、月结账单、人工收款和应收跟进工作台，不是在线支付、电子发票或完整财务系统。

确认采用以下方案：

1. 账单管理与配送管理继续保留两个独立菜单和页面；
2. 保留按单账单，并增加独立月结账单；
3. 月结账单由系统按客户结算周期自动生成草稿；
4. 自动生成后必须由获得账单权限的客服核对、调整、确认并发送，不自动对外发送；
5. 系统自动汇总账单，不自动确认客户已经付款；收款事实继续通过人工收款记录维护；
6. 不接真实支付网关，不做退款、银行自动对账、电子发票和财务审批；
7. 参考页中的配送状态、承运商、预约取件和物流追踪全部移入配送管理。

## 2. 参考文件映射

客服端参考页 `page-billing` 提供逾期提醒、账单快捷筛选、账单队列、账单操作和配送追踪。当前项目已将账单与配送拆为两个菜单，因此本页只继承账单部分的视觉和交互语言。

医生端参考页将账单分为“按单账单”和“月结账单”两个标签。月结账单展示月结单编号、结算周期、诊所、订单数、应收合计、已收金额、未收金额、收款状态和账单状态。

参考原型中的月结单是静态演示数据，没有真正实现自动生成。自动生成月结单是本项目此次确认新增的目标能力，不能误写为当前已有功能。

## 4. 按单账单

按单账单与一个订单关联。客服可以：

- 上传或更换真实账单文件；
- 填写真实账单编号、应收金额、币种和到期日；
- 查看、预览和下载账单文件；
- 登记人工收款记录；
- 查看应收、已收和未收金额；
- 从账单详情发起收款提醒；
- 查看关联订单和账单操作记录。

“上传账单”不能写成“创建发票”。账单编号按真实业务账单填写，不自动伪造成税务发票号。

## 5. 自动生成月结账单

### 5.1 目标流程

```text
到达诊所月结日
      ↓
系统读取该诊所的月结规则
      ↓
筛选本结算周期内符合条件且未被其他月结单占用的订单账单
      ↓
生成月结账单草稿和订单明细快照
      ↓
授权客服核对、排除或调整明细
      ↓
客服确认月结账单
      ↓
发送给诊所/医生
      ↓
人工登记收款：待收款 → 部分收款 → 已收款
```

### 5.2 自动生成与自动结算的边界

自动生成只负责：

- 按结算周期筛选符合条件的订单账单；
- 创建月结账单编号；
- 保存结算周期和订单明细快照；
- 汇总订单数量和应收金额；
- 根据客户账期计算到期日；
- 防止同一订单重复进入多个有效月结单。

自动生成不负责：

- 自动认定客户已经付款；
- 自动从银行或支付平台获取流水；
- 自动发送未经客服确认的账单；
- 自动处理退款、冲销、财务审批或税务发票；
- 使用当前产品价格反向重算历史订单金额。

### 5.3 自动生成前必须具备的客户配置

每个启用月结的诊所至少需要：

- 结算方式：月结；
- 结算周期，例如自然月；
- 月结生成日；
- 付款账期，例如 30、45 或 60 天；
- 币种；
- 账单接收账号或联系人；
- 月结状态：启用或停用。

缺少必要配置时不生成错误账单，应进入“生成异常”队列并提示客服补充客户结算资料。

### 5.4 待客户进一步确认的生成规则

页面方案已确认采用自动生成，但以下业务规则仍需在实施前取得客户口径：

1. 订单在生产完成、终检通过、发货还是按单账单上传后计入月结；
2. 加急费、返工折扣、补差价和其他调整如何进入月结；
3. 作废账单、跨期调整和已部分收款订单如何处理；
4. 一个诊所存在多币种时是否拆分月结单；
5. 月结日遇节假日或系统停机时如何补生成。

在规则确认前只冻结页面和目标流程，不自行编造计算口径。

## 6. 月结账单列表

月结账单标签页显示：

| 字段 | 内容 |
| --- | --- |
| 月结单编号 | 例如 `STMT-2026-07-0001` |
| 结算周期 | 起止日期 |
| 诊所 | 月结客户名称 |
| 订单数量 | 当前月结单包含的订单数 |
| 应收合计 | 明细账单金额快照合计 |
| 已收金额 | 有效人工收款记录合计 |
| 未收金额 | 应收合计减已收金额 |
| 账单状态 | 草稿、待客服确认、已发送、已作废 |
| 收款状态 | 待收款、部分收款、已收款、无需收款 |
| 到期日 | 按客户账期计算或由授权人员调整 |
| 异常标记 | 生成失败、配置缺失、金额待核对、已逾期等 |

## 8. 状态口径

“账单状态”和“收款状态”分开维护：

| 类型 | 状态 | 含义 |
| --- | --- | --- |
| 按单账单状态 | 待上传、已上传、已发送、已作废 | 账单文件及发送进度 |
| 月结账单状态 | 草稿、待客服确认、已发送、已作废 | 自动生成后的审核与发送进度 |
| 收款状态 | 待收款、部分收款、已收款、无需收款 | 实际收款进度 |
| 风险标记 | 已逾期、金额待核对、生成异常 | 可与账单和收款状态同时存在 |

“已逾期”不是收款状态。满足“已超过到期日且未收金额大于零”时显示逾期标记。

## 9. 人工收款记录

人工收款记录至少包含：

- 收款金额和币种；
- 收款方式；
- 收款时间；
- 收款备注；
- 登记人和登记时间；
- 关联按单账单或月结账单。

系统根据有效收款记录自动计算已收和未收金额。收款事实不允许无痕删除；录入错误应通过后续更正或冲销机制处理并保留审计记录。

## 10. 收款提醒联动

“发起收款提醒”进入对应订单或客户的问单沟通：

- 自动带入账单编号、应收金额、未收金额和到期日；
- 客服可以自由编辑提醒内容；
- 由客服人工确认发送，不使用自动群发固定话术；
- 发送结果回写账单操作记录；
- 月结账单提醒以诊所为对象，不为每个明细订单重复创建提醒。

## 11. 权限边界

| 角色 | 页面与数据范围 | 权限 |
| --- | --- | --- |
| 客服经理 | 全部客户账单 | 查看、上传、调整、确认月结单、记录收款、发起提醒 |
| 获得账单权限的高级客服 | 分配给自己的客户 | 按授权处理账单和月结单 |
| 普通客服 | 默认不可见 | 只在订单或问单中查看必要账单摘要 |
| 翻译人员 | 不可见 | 无账单权限 |
| 管理员 | 只读账单总览 | 查看账单、月结单和收款记录，不登记业务数据 |
| 医生/诊所 | 医生端只读 | 查看本诊所获授权的账单、月结单和收款状态 |
| 生产人员 | 不可见 | 只读取是否满足发货条件的业务结果 |

菜单隐藏不能代替后端权限和数据范围校验。月结生成、明细调整、确认发送、账单文件、收款记录和导出接口必须使用一致的权限控制。

## 12. 不在本页处理的内容

| 非本页职责 | 正确去向 |
| --- | --- |
| 客户结算方式、账期和账单联系人配置 | 客户管理 |
| 产品基础价 | 产品管理 |
| 单个订单最终应收金额来源和调整依据 | 订单业务及账单审核流程 |
| 承运商、运单号和物流异常 | 配送管理 |
| 与客户沟通收款事项 | 问单沟通 |
| 真实支付渠道、退款、对账和税务发票 | 当前不实现，需另行立项 |

## 13. 当前系统缺口与后续实施项

自动月结尚未实现，后续执行至少需要补齐：

1. 当前只有 `order_bill`，且通过 `order_id` 唯一约束限制为一单一账单；无法表达一张月结单包含多笔订单；
2. 当前没有月结账单主表、月结明细表、生成批次、金额快照和调整审计；
3. 当前客户档案没有完整的结算周期、生成日、账期、币种和月结启停配置；
4. 当前没有账单列表接口、月结列表/详情接口、自动生成接口和生成异常接口；
5. 当前没有月结定时任务、补偿任务、并发锁和防重复生成机制；
6. 当前按单账单响应未完整提供账单编号、到期日、发送状态和逾期依据；
7. 当前收款记录只关联订单，无法直接关联月结账单；
8. 当前收款状态由人工更新，尚未与有效收款记录自动核对；
9. 当前只有顶层 `CS` 角色，账单专项权限、客服岗位层级和客户数据范围尚未落实；
10. 当前后端允许 CS 和 ADMIN 写入账单及收款记录，与目标“授权客服处理、管理员只读”不一致；
11. 当前客服账单入口复用配送页面，没有本确认稿中的独立账单队列、月结页签和详情抽屉；
12. 项目历史范围将月结自动归集列为未实现/后续能力，本次确认构成新增目标，实施时必须同步更新接口、迁移、测试和项目验收文档。

## 14. 实施边界

- 账单管理业务方案已经冻结，当前只执行前端 HTML 像素校准；自动月结后端仍受下述业务规则门禁约束；
- 自动月结必须先完成业务规则确认，再进入开发；
- 自动生成失败不能产生半成品有效账单或重复占用订单；
- 已确认并发送的月结单使用快照和审计，不能静默重算；
- 实施后需覆盖自动生成、重复执行、跨期、调整、作废、部分收款、逾期、权限和客户数据范围验收；
- 不得把自动生成月结单表述成自动收款或真实支付平台已经接入。
