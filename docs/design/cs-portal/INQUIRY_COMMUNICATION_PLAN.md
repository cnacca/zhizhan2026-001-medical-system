# 客服端问单沟通页面确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-18
> 菜单位置：问单沟通
> 参考方式：以客服端 `page-comms` 的消息中心为视觉母版，保留双栏会话和真实消息交互

## 1. 页面定位

“问单沟通”是参考 HTML 中 `Comms Centre / Communications Centre` 的业务升级版，不是新增一套孤立消息系统。

页面统一承接：

- 补资料问单；
- 翻译疑点；
- 设计确认；
- 订单信息确认；
- 交期、账单、配送等客户沟通；
- 生产人员提交、需要客服审核后才能发给客户的消息。

本页不等于“通知中心”。问单沟通是围绕具体订单的双向会话；通知中心只处理系统提醒和已读/未读。

## 2. 已确认的会话组织规则

采用“一订单一会话，会话内包含多个问单事项”：

```text
订单会话 ORD2026...
├── 补充资料              已完成
├── 翻译疑点              已完成
├── 设计确认 V3           等待客户回复
└── 该订单持续保留的完整聊天记录
```

确认细则：

- 左侧每一行对应一个订单会话，同一订单不因问单类型拆成多个聊天窗口；
- 右侧保留该订单的连续历史消息；
- 同一会话可以同时存在多个问单事项，每个事项独立记录类型、来源、状态和结果；
- 事项完成后可关闭，但订单会话和历史消息永久保留；
- 工作台统计未完成问单事项数，不统计消息条数。一个会话中有两个未完成事项，工作台计为 2 个待处理问单。

该规则与参考 HTML 一致：参考文件的 `comms_data` 按订单/病例编号建立会话，每个会话内保存多条 `msgs`，不按每条消息或每个问题重复建立左侧会话。

## 4. 右侧是真实自由会话

右侧不是固定话术操作区，而是可持续交流的完整聊天窗口：

- 展示完整历史聊天记录，并支持独立滚动；
- 客服可以自由输入文字、连续追问和补充说明；
- 支持发送图片、订单文件和设计稿；
- 支持 AI 翻译辅助，但 AI 不自动发送消息；
- 客户回复进入同一订单会话，不重新生成独立会话；
- 快捷话术只是可选模板，点击后填入输入框，允许客服修改，不得直接自动发送；
- 消息持久保存并关联订单、发送人、发送时间和可见范围。

## 5. 问单事项与状态

会话状态用于左侧快速筛选：

- 待客服处理；
- 等待客户回复；
- 客户已回复；
- 有未完成事项；
- 已完成。

事项类型使用独立筛选，不与状态混用：

- 补充资料；
- 翻译疑点；
- 设计确认；
- 订单信息确认；
- 交期问题；
- 账单/配送；
- 生产消息。

默认排序为：客户已回复待处理 → 生产消息待客服审核 → 新建待发送问单 → 超时等待客户 → 普通等待 → 已完成。

## 6. 事项卡与来源映射

| 问单来源 | 右侧事项卡 | 处理结果回写 |
| --- | --- | --- |
| 订单管理 | 缺失资料、待确认订单字段 | 回写订单资料和相关状态 |
| 信息审核/翻译 | 客户原文、翻译人员疑点 | 回写客户回复，任务进入“待二次确认” |
| 设计稿管理 | 设计预览、版本、确认范围 | 回写确认、驳回和修改意见 |
| 生产相关页面 | 拟对客发送内容和内部说明 | 回写客服审核和发送结果 |
| 客户管理 | 从客户详情查看该客户的历史订单会话 | 不直接修改订单状态 |

事项卡只用来告诉客服“为什么沟通、现在处理到哪里”，不得替代自由聊天。

## 7. 设计确认流程

```text
设计稿管理内部审核通过
      ↓
在对应订单会话中新增“设计确认”事项
      ↓
客服检查并发送给客户
      ↓
客户确认 / 要求修改 / 补充意见
      ↓
结果回写设计稿管理
      ↓
确认：锁定当前版本
修改：制作新版本，在同一订单会话再次发起确认
```

客服可以解释、追问、催复和记录客户意见，但不能代替客户确认设计稿。

## 8. 权限与内外部隔离

| 角色 | 权限 |
| --- | --- |
| 客服 | 自由发送对客消息、跟进回复、处理和关闭客服问单 |
| 翻译人员 | 提交翻译疑点、查看关联客户答复；不直接对客发送 |
| 设计人员 | 查看设计修改意见；不代替客户确认 |
| 生产人员 | 提交对客消息草稿；客服审核后才能发送 |
| 客户/医生 | 只看对客消息和允许暴露的订单内容 |
| 客服经理 | 查看全部会话、转派负责人和监督超时事项 |

客户/医生不得看到内部备注、人员、工序、入检/出检、工时、返工、绩效、责任分类和内部审核记录。

## 9. 默认业务口径

- 只有客服可以向客户发送消息；
- 快捷话术只是可编辑模板，不自动发送；
- 设计确认必须由客户明确确认或要求修改；
- 问单事项完成后关闭，会话和历史消息保留；
- 第一期只处理平台内消息，不接入微信、WhatsApp、邮件等外部渠道。

## 10. 当前系统缺口与后续实施项

以下缺口已记录，但不在本轮方案讨论阶段实施：

1. 当前已有订单消息、消息审核、关注事项和设计确认基础接口，但没有统一的问单事项实体；
2. 当前缺少问单类型、来源、负责人、状态、关闭结果和关联业务对象；
3. 当前设计确认没有在会话中呈现为包含版本、预览和结果的事项卡；
4. 当前会话附件能力不完整，需补齐图片、订单文件和设计稿的私有访问；
5. 当前需补齐真实发送时间、未读数、负责人、超时提醒和结果回写；
6. 当前生产草稿、内部说明和对客消息的展示仍需进一步隔离；
7. 实施时必须保留参考 HTML 的双栏会话布局、搜索、会话列表、消息时间线、自由输入和快捷模板交互。
