# 客服端信息审核/翻译页面确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-17
> 菜单位置：订单管理 → 信息审核/翻译
> 参考方式：组合使用客服端 `page-datacenter` 的处理队列与 `page-comms` 的双栏工作区语言

## 1. 页面定位

“信息审核/翻译”是翻译人员的专属处理工作台，不是客服审单页面。页面负责审核客户文字信息、完成翻译、整理供生产执行的最终信息，并把无法自行确认的疑点提交给客服发起问单。

本页形成订单级翻译确认稿、结构化生产信息和生产备注，作为后续设计稿管理和生产审核的业务基线。设计稿管理可以为具体设计版本保存调整值，但不能反向覆盖本页的订单级确认记录。

确认的职责原则：

- 翻译人员负责信息审核、翻译、术语校对和生产信息整理；
- 普通客服不在本页审核订单、保存翻译稿或确认生产备注；
- 翻译人员发现疑点时只创建问单事项，不直接联系客户；
- 客服在“问单沟通”中向客户确认，回复结果回到本页；
- AI 只生成草稿，最终内容必须由翻译人员人工确认；
- 原文、AI 草稿、人工确认稿和处理记录分别保存，不得互相覆盖。

## 5. 其他页签

### 5.1 附件

- 展示客户原始附件的文件名、类型、大小和上传时间；
- 使用私有文件和短时效签名 URL 完成预览与下载；
- 翻译人员可以查看与文字要求有关的附件，不得修改或删除客户原始附件；
- 无权限、链接过期和预览失败必须有明确反馈。

### 5.2 处理记录

按时间倒序展示：

- 任务创建、分配和开始处理；
- AI 草稿生成；
- 人工草稿保存和版本变化；
- 疑点标记、问单创建和客户回复；
- 最终稿确认与任务完成。

## 6. 状态定义

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| 待翻译审核 | 新订单已经登记，尚未开始信息处理 | 翻译人员开始处理 |
| 处理中 | 已有翻译人员编辑审核 | 保存草稿、标记疑点或完成 |
| 待问单 | 已发现疑点，但尚未提交客服沟通 | 提交问单事项 |
| 等待客户回复 | 客服已经发出问单 | 等待结果回写 |
| 待二次确认 | 客户已回复，需要翻译人员复核 | 更新确认稿和生产信息 |
| 已完成 | 信息和翻译已经人工确认 | 进入生产审核 |

默认排序：加急订单 → 客户已回复待二次确认 → 等待时间最长的待翻译审核 → 普通处理中任务 → 已完成。

## 7. 问单联动

```text
翻译人员发现信息疑点
      ↓
填写疑点说明并提交问单事项
      ↓
系统创建待处理问单，任务状态改为“等待客户回复”
      ↓
客服在问单沟通中联系客户
      ↓
客户回复并形成可追溯沟通记录
      ↓
本页状态改为“待二次确认”
      ↓
翻译人员更新最终稿并完成任务
```

翻译人员不能直接在本页向客户发送消息。问单关闭前，如果疑点影响生产执行，“完成信息审核/翻译”按钮保持禁用。

## 8. 页面职责边界

本页负责：

- 审核客户文字信息是否完整、明确和一致；
- 查看全部动态订单字段；
- 翻译外文内容和校对专业术语；
- 整理最终生产执行信息和生产备注；
- 保存原文、AI 草稿、人工确认稿和版本；
- 标记疑点并创建问单事项；
- 在客户回复后完成二次确认。

本页不负责：

| 非本页职责 | 正确去向 |
| --- | --- |
| 登记新订单 | 订单管理 |
| 直接联系客户 | 问单沟通 |
| 设计稿版本、设计版本参数调整和内部审核 | 设计稿管理 |
| 对外设计确认 | 问单沟通 |
| 生产可行性审核 | 生产端 |
| 账单、配送和外协操作 | 对应业务页面 |

订单级生产信息与设计版本执行信息必须分别保存：前者由本页确认，后者只在存在设计稿的订单中由设计稿管理维护。两个版本存在差异时必须显示来源和修改记录，不能互相静默覆盖。

## 9. 角色权限

| 角色 | 权限 |
| --- | --- |
| 翻译人员 | 查看分配任务、编辑、翻译、提交疑点、确认最终稿、完成处理 |
| 普通客服 | 默认不显示该菜单；只在问单沟通中处理翻译人员提交的问题 |
| 客服经理 | 查看队列、分配任务和监督进度；默认不直接修改翻译内容 |
| 生产人员 | 只能读取已经人工确认的最终生产信息 |
| 医生/客户 | 不能查看内部翻译草稿、AI 内容、生产备注和处理记录 |

菜单隐藏不能代替权限控制。列表、详情、草稿、附件、AI 调用、提交和导出接口必须使用相同的角色与数据范围校验。

## 10. 当前缺口与后续实现项

以下缺口已记录，但不在本轮方案讨论阶段实施：

1. 当前后端只有 `DOCTOR / CS / WORKER / ADMIN` 四类顶层角色，没有翻译人员岗位或专项权限；
2. 当前翻译、资料缺失检查和生产备注接口主要授权给 `CS / ADMIN`，与新职责不一致；
3. 当前页面仍使用“需客服确认”“客服确认翻译稿”等旧口径；
4. 当前翻译草稿、资料缺失检查和生产备注能力散落在订单初审页面；
5. 当前没有独立的信息审核/翻译任务、负责人、状态、等待时长和版本记录；
6. 当前没有从翻译疑点创建问单、等待回复和结果回写的完整关联；
7. 当前订单状态机仍依赖客服初审通过后进入生产审核，与客户确认的新流程不一致。

后续实施需要：

- 增加翻译岗位或 `translation:review` 专项权限；
- 将翻译和信息审核接口授权给翻译人员；
- 禁止普通客服保存翻译稿或确认生产备注；
- 增加任务状态、负责人、开始/完成时间和审核版本；
- 增加问单关联、回复回写和未解决疑点门禁；
- 把“客服确认翻译稿”统一改为“翻译人员人工确认”；
- 调整订单状态机，使信息审核/翻译完成后进入生产审核；
- 为岗位、数据范围、附件和 AI 调用补齐后端权限测试。

以上缺口不得用前端静态状态、演示数组或 `localStorage` 假装完成。

## 11. 页面反馈状态

至少覆盖：

- 首次加载、加载中、加载失败；
- 队列为空、筛选无结果；
- 草稿未保存时切换任务；
- AI 草稿生成中、失败、限流和预算保护；
- 附件无权限、预览失败和签名链接过期；
- 问单创建成功、失败和重复提交；
- 等待客户回复、客户已回复和待二次确认；
- 最终保存冲突、任务已被他人处理和权限不足；
- 存在未解决疑点时禁止完成任务。

## 12. 实施与验收边界

- 设计方案和缺口已经冻结，当前只执行前端 HTML 像素校准；
- 翻译岗位、任务、版本和问单回写等后端能力仍按缺口管理，不用静态前端状态冒充完成；
- 不复制参考 HTML 的演示数据或 `localStorage` 状态；
- 不允许 AI 草稿自动发送、自动写入订单或绕过人工确认；
- 不允许普通客服代替翻译人员完成信息审核；
- 不允许医生/客户读取内部翻译草稿和生产备注；
- 实施后需覆盖翻译人员、普通客服、客服经理、生产人员和医生的权限差异；
- 在 `1440×900` 下保存默认队列、信息审核、翻译编辑、待问单、等待回复、待二次确认和完成状态截图。
