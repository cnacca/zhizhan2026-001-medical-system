# 客服端产品管理页面确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-18
> 菜单位置：产品管理
> 参考边界：三份参考 HTML 均没有产品管理页；本页是项目专属页面，只复用客服端的快捷筛选、表格、状态和详情面板视觉语言

## 1. 已确认的页面定位

客服端“产品管理”只维护已经存在于平台的产品：

- 维护产品名称、产品类型、材料规格、人工基础价、币种、价格说明和启停状态；
- 维护医生选择该产品后需要填写的具体内容，页面业务名称统一为“医生下单要求”；
- 查看产品资料和医生下单要求的变更记录。

本轮明确不做：

- 不提供“新增产品”按钮或接口入口；
- 不新增“产品需求”队列；
- 不假定医生、客服、生产或管理员中任何一方可以创建全局新产品；
- 不自行设计新产品的来源、审批或发布流程；
- 不显示“模板待完善”“模板有草稿”等未经确认的模板级状态。

## 2. 参考文件事实

参考门户的产品是预先写入原型的固定分类和子类型：

- 医生端只能在新订单流程中选择已有产品分类和子类型；
- 客服端可以协助新建订单，但同样只能选择已有产品；
- 生产端只读取订单中的产品；
- 参考文件没有新产品申请、审批、创建或发布流程。

因此，产品管理页只处理已有产品，不用未经确认的项目流程反向解释参考原型。

## 3. 产品与订单的关系

产品是可被多个订单重复使用的全局产品目录，不属于任何单一订单；医生创建订单时会选择一个已启用产品。

```text
全局产品目录
├── 常规牙冠
├── 种植牙冠
└── 贴面
        ↓ 被订单引用
订单 A：种植牙冠
订单 B：贴面
```

修改产品不得反向覆盖已创建订单的产品和填写内容。正式实施应使用真实产品目录限制医生可选项，不继续使用任意文本产品类型。

## 5. 产品详情面板

点击“查看”后打开与参考订单详情一致的右侧 `540px` 详情抽屉，抽屉全高，正文独立滚动。

```text
┌────────────────────────────────────────────────────────────┐
│ 常规牙冠                                      [启用] [×]    │
│ REGULAR_CROWN · 最近更新 2026-07-18                         │
├───────────────────────────────────────────────────────────┐
│ 产品资料          医生下单要求          变更记录               │
├───────────────────────────────────────────────────────────┐
│ 产品名称        [常规牙冠________________________]           │
│ 产品类型        [REGULAR_CROWN]              创建后不可修改 │
│ 材料规格        [氧化锆、玻璃陶瓷______________]             │
│ 基础价格        [680.00]       币种 [CNY ▼]                 │
│ 价格说明        [人工维护基础价，不代表最终结算价]           │
│ 当前状态        [启用 ▼]                                    │
│                                                              │
│ 修改原因        [________________________________________]           │
├───────────────────────────────────────────────────────────┐
│ [停用产品]                              [取消] [保存修改]  │
└───────────────────────────────────────────────────────────┘
```

基础价是客服端人工维护的内部参考价，不是医生报价、客户专属价或订单最终应收金额。种子占位价或未确认价格统一显示“价格待确认”。

## 6. 医生下单要求

“医生下单要求”回答“医生选择该产品后，需要提供哪些具体内容”。页面直接展示业务内容，不在产品列表中显示抽象数量。

```text
┌──────────────────────────────────────────────────────────┐
│ 医生选择“常规牙冠”后，需要提供以下内容                  │
├───────────────────────────────────────────────────────────┐
│ 信息名称    是否必须填写    填写方式           可选内容             │
│ 牙位        必须填写        牙位选择           —                    │
│ 材料        必须填写        单项选择           氧化锆 / 玻璃陶瓷    │
│ 色号        必须填写        单项选择           A1 / A2 / A3 ……      │
│ 咬合要求    选填            文字说明           —                    │
│ 医生备注    选填            多行文字           —                    │
├───────────────────────────────────────────────────────────┐
│ [添加填写要求] [调整顺序] [预览医生下单页面]                  │
└───────────────────────────────────────────────────────────┘
```

统一使用业务词：

| 不向客服展示的技术词 | 页面业务用词 |
| --- | --- |
| 动态表单 / 下单模板 | 医生下单要求 |
| 字段 | 填写要求 / 信息名称 |
| 字段类型 / 控件类型 | 填写方式 |
| 字段选项 | 可选内容 |
| 必填标记 | 是否必须填写 |

当前不设计模板草稿、版本或发布状态。修改医生下单要求后，只影响修改后创建的新订单，不覆盖历史订单已保存的内容。

## 7. 变更记录

产品资料、基础价格、启停状态和医生下单要求的每次变更至少记录：

- 修改对象和修改内容；
- 修改前和修改后的值；
- 修改人和修改时间；
- 修改原因；
- 启用、停用和恢复等状态操作。

产品和医生下单要求不物理删除，停用后仍可以在历史订单和变更记录中查看。

## 8. 权限边界

| 角色 | 产品管理页 | 权限 |
| --- | --- | --- |
| 客服经理 | 可见 | 维护已有产品资料、基础价格、启停状态和医生下单要求；不新增产品 |
| 获得产品维护权限的高级客服 | 可见 | 按授权维护已有产品和医生下单要求；不新增产品 |
| 普通客服 | 不可见 | 在订单页查看已选产品摘要，不管理产品 |
| 翻译人员 | 不可见 | 只在信息审核/翻译任务中查看必要产品资料 |
| 管理员 | 只读产品总览 | 查看产品资料和启停状态；不新增、编辑、停用或管理医生下单要求 |
| 医生/客户 | 不可见 | 下单时只选择已启用产品并填写对应要求；不查看内部基础价 |
| 生产人员 | 不可见 | 只读取订单已保存的产品和生产执行信息，不管理产品目录 |

菜单隐藏不能代替后端校验。产品列表、详情、价格、启停状态、医生下单要求和变更记录接口必须使用同一产品维护权限校验。

## 9. 页面职责边界

本页不处理：

| 非本页职责 | 正确去向 |
| --- | --- |
| 新产品申请、来源和审批 | 当前不实现，待客户明确业务流程 |
| 客户专属价、折扣和合同条款 | 客户管理 |
| 订单最终应收金额 | 账单管理 |
| 生产工序链和工艺参数 | 生产端/工艺管理 |
| 材料库存、采购和损耗 | 物料管理 |
| 产品实际生产成本 | 成本管理 |
| 单个订单的产品和客户指示 | 订单管理、信息审核/翻译或设计稿管理 |

## 10. 当前系统缺口与后续实施项

以下缺口已记录，但不在本轮方案讨论阶段实施：

1. 当前客服产品页仍显示“新增产品”并调用 `POST /products`，与本次确认口径冲突；
2. 当前 `/products` 允许 CS 和 ADMIN 读写，目标权限要求管理端只读、客服端只对授权岗位开放既有产品维护；
3. 当前 `/form-configs` 写入只授权 ADMIN，与“产品和医生下单要求由客服端维护”的目标冲突；
4. 当前医生端使用可任意输入的产品类型文本，没有从已启用产品目录中选择；
5. 当前订单、产品目录和医生下单要求只通过 `product_type` 字符串弱关联，没有产品外键或完整产品快照机制；
6. 当前没有产品资料、基础价、启停状态和医生下单要求的完整变更记录；
7. 当前前端使用“动态表单”“字段”“类型”“选项”等技术词，实施时必须替换为本文件确认的业务语言；
8. 当前没有模板草稿、版本或发布能力；本次确认不新增这些能力，也不在页面展示相关状态。
