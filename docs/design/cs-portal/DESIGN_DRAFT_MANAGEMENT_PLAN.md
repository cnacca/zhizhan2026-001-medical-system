# 客服端设计稿管理页面确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-17
> 菜单位置：订单管理 → 设计稿管理
> 参考方式：组合使用客服端 `page-orders` 的列表和 `540px` 详情面板语言；参考 HTML 没有独立设计稿管理页面

## 1. 客户反馈解释

客户提出：“这个设计稿管理页面，最好可以体现出产品、颜色、牙位还有客户给的全部指示，我们只需要在上面的信息上做出更改、审核和添加。”确认口径如下：

- 设计稿管理不是单纯的文件列表，而是以订单为核心的设计审核工作区；
- 列表和详情必须显示产品、颜色/色号、牙位以及客户提交的全部指示；
- 获得设计稿权限的客服可以修订当前设计版本的执行信息、补充说明、添加设计稿版本并完成内部审核；
- 客户原始指示永久保留，不允许被客服修订直接覆盖；
- 设计稿管理保留独立菜单和页面；
- 设计确认不建立独立页面：由设计稿管理发起，在问单沟通中完成。

## 4. 信息展示与修改规则

### 4.1 客户原始指示

客户原始指示只读并永久保留。页面不能只读取四个硬编码字段，应结合订单动态表单配置，完整展示客户填写的全部业务字段，例如：

- 产品和材料；
- 颜色、色号和渐变要求；
- 牙位、缺失牙和修复范围；
- 咬合、邻接、形态、边缘和固位要求；
- 医生备注、客户特殊要求和交期说明；
- 客户上传附件的说明与关联关系；
- 当前产品模板中的其他动态字段。

### 4.2 当前设计版本执行信息

信息审核/翻译页面形成订单级翻译确认稿、结构化生产信息和生产备注；设计稿管理只把这些内容作为只读基线。获得设计稿权限的客服可以为当前设计版本补充或修订设计执行值，但不能在本页改写订单级确认稿。

每次修改当前设计版本执行值必须保存：

- 修改前内容；
- 修改后内容；
- 修改人；
- 修改时间；
- 修改原因或补充说明。

产品、色号、牙位和执行说明的设计版本值，必须与客户原始值、订单级翻译确认值并存。存在差异时，页面明确标记“本设计版本已调整”，不能无痕覆盖客户原始提交或信息审核/翻译确认稿。

没有设计稿环节的订单直接使用信息审核/翻译形成的订单级生产信息；只有进入设计稿流程的订单才产生设计版本调整。

### 4.3 添加能力

“添加”包括：

- 添加客服补充说明；
- 关联已有订单文件；
- 添加新的设计稿版本；
- 为新版本填写上传说明；
- 在驳回后上传修订版本。

## 5. 列表状态与排序

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 待生产上传 | 订单需要设计稿，但生产端尚未上传 | 查看订单要求、提醒生产 |
| 待客服审核 | 生产已上传新版本，等待客服核对 | 预览、通过或驳回 |
| 待客户确认 | 客服已通过并发起设计确认 | 进入问单沟通查看进展 |
| 驳回/待修改 | 客服或客户提出修改，等待新版本 | 查看原因、追加版本 |
| 已确认 | 客户已确认当前版本 | 查看最终版本和确认记录 |

默认按“待处理优先、最近更新时间倒序”排列。状态优先级为：待客服审核 → 驳回/待修改 → 待生产上传 → 待客户确认 → 已确认。

## 6. 设计稿管理与问单沟通的关系

```text
生产上传设计稿
      ↓
设计稿管理
客服对照订单级确认信息，核对当前设计版本的产品、色号、牙位和客户全部指示
      ↓
审核通过并发起设计确认
      ↓
系统创建“设计确认”问单
      ↓
问单沟通
客户查看设计稿并确认 / 驳回 / 留言
      ↓
确认结果自动回写设计稿版本状态
```

职责划分：

| 操作 | 所属页面 |
| --- | --- |
| 查看、预览和管理设计文件 | 设计稿管理 |
| 修订当前设计版本的产品、色号、牙位和设计执行要求 | 设计稿管理 |
| 订单级翻译确认稿、生产信息和生产备注 | 信息审核/翻译 |
| 添加设计稿版本 | 设计稿管理 |
| 客服内部审核 | 设计稿管理 |
| 发起设计确认 | 设计稿管理中的触发按钮 |
| 向客户发送设计稿 | 问单沟通 |
| 客户确认、驳回和修改意见 | 问单沟通 |
| 查看确认结果和版本状态 | 两个页面同步展示 |

不建立独立的“设计确认”菜单或页面。

## 7. 角色权限

| 角色 | 主要能力 |
| --- | --- |
| 生产人员 | 上传新设计稿版本、查看退回原因；不能代表客户确认 |
| 获得设计稿权限的客服 | 查看客户指示和订单级确认信息、修订当前设计版本执行信息、预览、审核、驳回、发起设计确认 |
| 客服经理 | 查看全部客户的设计记录、监督审核进度；具体修改能力按岗位授权控制 |
| 医生/客户 | 只在对外问单上下文中查看授权版本并确认、驳回或留言 |

设计文件预览继续使用私有文件和短时效签名 URL。医生/客户不能读取内部版本、客服内部备注、生产人员或内部审核记录。

## 8. 页面反馈状态

至少覆盖以下状态：

- 首次加载、加载中、加载失败；
- 无设计订单、筛选无结果；
- 无设计稿版本、文件预览失败；
- 保存执行信息中、保存成功、保存冲突；
- 审核中、审核失败、驳回原因缺失；
- 已有新版本导致当前审核过期；
- 发起设计确认成功，并提供“进入问单沟通”入口；
- 用户无权限、订单超出数据范围或签名链接过期。

## 9. 实施与验收边界

- 页面业务方案已经冻结，当前执行前端 HTML 像素校准；
- 不复制参考 HTML 的演示数据或 `localStorage` 状态；
- 不允许无痕覆盖客户原始指示；
- 不允许把“已发起设计确认”直接当成“客户已确认”；
- 不允许医生/客户读取内部设计版本、内部备注或审核人员信息；
- 实施后需验证列表筛选、详情打开、信息修改、版本添加、文件预览、通过、驳回、发起确认和问单回写；
- 在 `1440×900` 下保存默认列表、详情面板、编辑状态、驳回状态和确认结果的同尺寸截图。
