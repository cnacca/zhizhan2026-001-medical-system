# 客服端全局搜索页面重构确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-18
> 参考边界：顶栏 `240×30px` 搜索框直接映射参考 HTML；搜索建议弹层和完整结果页均为项目扩展，左侧栏不设置搜索结果页面

## 1. 设计结论

全局搜索采用“顶栏搜索建议弹层＋完整搜索结果页面”的两层结构：

1. 顶栏保留参考页 `240px` 搜索框；
2. 输入关键词后显示按业务分类的搜索建议；
3. 按回车或点击“查看全部搜索结果”进入完整结果页；
4. 搜索结果页不出现在左侧菜单中；
5. 进入结果页时保持原业务菜单激活，返回时恢复原页面状态；
6. 所有搜索结果必须在服务端应用岗位、客户、订单、消息和字段权限；
7. 点击结果时再次校验权限并定位具体业务记录；
8. 全局搜索不能仅依靠前端并发查询多个业务接口拼接结果。

## 2. 依据与参考边界

客服端参考 HTML 顶栏包含宽约 `240px` 的搜索框，提示可搜索订单、客户和问题，但没有搜索建议、搜索结果页或真实搜索逻辑。

当前项目的客服顶栏也显示“搜索订单、客户、消息”，但实际行为只是：

- 在订单页筛选订单；
- 在客户页筛选客户；
- 在产品页筛选产品；
- 在问单沟通页输入纯数字时按订单 ID 加载；
- 其他页面没有明确的搜索结果。

因此当前能力属于“当前页面筛选”，不能继续以“全局搜索”名义交付。目标方案补充真实跨业务搜索，但保留参考页的顶栏位置、尺寸、聚焦边框和紧凑视觉。

## 3. 顶栏搜索框

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 当前页面标题  [⌕ 搜索订单、客户、消息……]  数据时间  🔔  ❓  [＋ 新建订单] │
└──────────────────────────────────────────────────────────────────────────────┘
                          宽度：240px
```

搜索框规则：

- 默认宽度 `240px`，聚焦时边框改为客服端紫色；
- 输入两个及以上字符后触发建议搜索；
- 输入停止约 `250ms` 后发送请求，避免每次按键立即请求；
- 按回车进入完整结果页；
- 按 `Esc` 或点击外部区域关闭建议；
- 清空输入后关闭建议；
- 加载、失败和无结果都有明确状态；
- 不显示静态演示建议。

## 6. 搜索范围与页面映射

| 搜索类型 | 可检索内容 | 点击结果进入 |
| --- | --- | --- |
| 订单 | 订单号、产品、客户、允许检索的患者名称 | 订单管理对应详情 |
| 客户 | 诊所名称、联系人、客户编号 | 客户管理对应档案 |
| 问单沟通 | 订单号、会话标题、授权范围内的消息正文 | 问单沟通对应会话 |
| 设计稿 | 订单号、设计稿版本、文件名 | 设计稿管理对应版本 |
| 产品 | 产品名称、材料、产品编号 | 产品管理对应详情 |
| 账单配送 | 订单号、账单号、物流单号 | 账单管理或配送管理 |
| 外协 | 外协批次、订单号、合作方、外发地点 | 外协管理对应批次 |

信息审核/翻译任务通过关联订单号、客户和任务内容查询，点击后进入对应翻译任务，不单独增加重复分类。

## 7. 搜索结果卡片

每条结果统一显示：

- 业务类型图标；
- 主标题；
- 订单、客户、会话或批次上下文；
- 当前真实状态；
- 命中的内容摘要；
- 最近更新时间；
- 来源页面；
- 查看详情操作。

关键词使用加粗或浅紫背景突出，但所有命中摘要必须先进行安全转义，不能把消息、客户指示或文件名作为 HTML 直接渲染。

## 8. 点击与返回逻辑

```text
输入关键词
    ↓
服务端按当前账号权限搜索
    ↓
返回已经脱敏和授权的分类结果
    ↓
点击搜索结果
    ↓
目标接口再次校验数据权限
    ↓
打开对应订单、客户、会话、设计稿或业务批次
    ↓
关闭详情后恢复原搜索结果、筛选和滚动位置
```

如果记录已经不存在、缺少定位信息或账号失去权限：

- 显示“该记录当前不可访问”；
- 不打开其他客户或全部订单；
- 不通过摘要继续展示已经失去权限的数据；
- 不提示“记录存在但你无权限”，避免侧信道泄露。

## 9. 权限与隐私

- 客服只能搜索本人客户范围内的订单、客户、问单和业务记录；
- 客服经理可以搜索全部客户及团队业务数据；
- 翻译人员只搜索可处理的翻译任务和关联问单；
- 无设计稿权限的账号不能看到设计文件名；
- 无账单权限的账号不能看到金额、付款状态和账单文件；
- 消息正文搜索继续执行订单、会话和消息可见性校验；
- 患者名称只能在有权访问对应订单时检索和展示；
- 搜索结果不得返回密码、Token、内部密钥、对象存储路径和未授权生产字段；
- 点击结果必须再次校验目标业务权限，不能把搜索授权当成长期授权。

患者名称、客户消息等敏感关键词不写入普通前端日志、分析埋点或长期最近搜索历史。

## 10. 空状态与异常

```text
没有找到“A-1024”的相关结果

可以尝试：
· 检查订单号或外协批次号
· 缩短搜索内容
· 搜索客户或产品名称
· 确认当前账号是否负责该客户

[清空搜索]
```

页面分别处理：

- 关键词为空；
- 关键词不足两个字符；
- 当前权限范围内无结果；
- 部分分类暂时不可用；
- 搜索请求失败；
- 目标详情当前不可访问。

搜索无结果不代表记录不存在，页面不能暴露无权访问记录的存在性。

## 11. 技术实现方向

后续实施应提供统一客服全局搜索聚合接口，由服务端：

1. 解析搜索关键词和请求分类；
2. 根据当前账号岗位和数据范围确定允许搜索的业务类型；
3. 分别执行订单、客户、消息、设计稿、产品、账单配送和外协查询；
4. 在数据查询阶段完成客户范围、订单范围和字段脱敏；
5. 返回统一的分类数量、结果摘要和安全目标标识；
6. 为建议弹层和完整结果页提供不同条数限制；
7. 对搜索频率、结果数量和查询耗时设置限制。

不建议让前端直接并发调用所有业务接口后自行合并，因为这会造成权限规则分散、请求数量过多和结果字段不一致。

## 12. 当前实现缺口

以下缺口已记录，但不在本轮方案讨论阶段实施：

1. 当前顶栏搜索只筛选部分当前页面，不是真正全局搜索；
2. 当前没有统一客服搜索接口和统一结果模型；
3. 当前订单、客户、产品和外协已有独立关键词查询，但返回结构不同；
4. 当前没有问单消息正文搜索；
5. 当前没有设计稿、账单、物流和信息审核任务的统一搜索入口；
6. 当前没有搜索建议弹层、分类数量、完整结果页和分页；
7. 当前没有按搜索结果直接定位具体会话、设计版本、账单、物流或外协批次；
8. 当前没有搜索页返回后恢复原业务页面状态的机制；
9. 当前未来客户分配和客服岗位层级尚未接入全部搜索查询；
10. 当前没有敏感搜索词日志治理、限流和查询审计口径。

## 13. 明确不做的功能

- 不在侧栏增加搜索结果菜单；
- 不使用前端静态数组制造搜索结果；
- 不跨越客户和订单数据范围；
- 不在结果卡片上提供审核、发送、删除或状态修改操作；
- 不把无权限记录计入结果数量；
- 不长期保存包含患者名称或客户消息的搜索历史；
- 不使用未经权限过滤的 AI 语义搜索；
- 不展示数据库主键、权限码或内部对象存储路径。

## 14. 实施边界

- 搜索入口、弹层、结果页、范围和权限方案已经冻结，当前只执行前端 HTML 像素校准；
- 顶栏搜索框按参考页 `240px` 视觉实现；
- 建议弹层和完整页面必须使用同一真实搜索数据源；
- 搜索结果页不改变侧栏菜单激活项；
- 点击结果定位具体记录并重新校验权限；
- 返回后恢复原页面和搜索结果状态；
- 像素校准完成后重新进行顶栏搜索、建议弹层、结果页、定位和返回状态验收。
