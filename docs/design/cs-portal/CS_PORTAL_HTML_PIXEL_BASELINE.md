# 客服端参考 HTML 像素实施基线

> 状态：已确认并进入实施
> 基准视口：`1440 × 900`
> 唯一视觉基准：`frontend/public/reference/cs-portal.html`
> SHA-256：`035c43e735fe73badbcc0612e176c4a974057c2d1418470b0c72ac089a7f304d`

## 1. 权威顺序

1. 业务职责、权限、状态词和已确认增删项，以本目录各页面确认稿为准；
2. 布局、尺寸、间距、字体、颜色、圆角、边框、阴影和交互容器，以参考 HTML 的 `1440 × 900` 实际渲染为准；
3. 项目没有直接参考页时，复用同一 HTML 的壳层、列表、卡片、抽屉和空状态语言，不虚构“直接映射”；
4. 正式页面只使用真实接口数据或明确空态，不复制参考文件中的姓名、订单、金额、数量和日期；
5. 不复制参考 HTML 已确认的缺陷：账单宽表必须在卡片内横向滚动，配送列表必须显示真实列表或空态。

## 3. 列表与详情

- 快捷筛选行：按钮间距 `6px`，行下间距 `14px`；按钮 `padding: 5px 13px`，实际高度约 `27–28px`；
- 表格工具栏：`padding: 10px 14px`，实际高度约 `49px`；
- 表头：`padding: 9px 13px`，实际高度约 `31px`；
- 单元格：`padding: 10px 13px`，不强行统一行高；订单行约 `63–77px`，资料行约 `47.5px`，账单行约 `51–62.5px`；
- 订单、设计稿等列表详情使用右侧 `540px × 100vh` 抽屉；抽屉头部按 `60px` 实施，正文 `padding: 16px 20px`；
- 弹窗默认最大宽度 `680px`、最大高度 `88vh`；配送弹窗最大宽度 `760px`；
- 宽表只能在表格卡片内部滚动，不能让整个页面出现横向滚动。

## 5. 映射边界

### 直接映射

- 工作台外壳 → `page-dashboard`
- 订单管理 → `page-orders` + 订单抽屉
- 问单沟通 → `page-comms`
- 客户管理 → `page-clients`
- 设置与账号 → `page-settings`

### 组合映射

- 信息审核/翻译 → `page-datacenter` + `page-comms`
- 设计稿管理 → `page-orders` + 订单抽屉
- 账单管理 → `page-billing` 的账单部分
- 配送管理 → `page-billing` 的配送部分

### 无直接参考页

产品管理、外协管理、通知完整页、帮助完整页和搜索结果页只复用参考组件语言，不声称像素复制某个不存在的页面。

## 6. 验收门禁

- 固定使用 `1440 × 900`，逐一进入 11 个侧栏页面和 3 个顶栏辅助入口；
- 检查标题、筛选、列表、抽屉、页签、自由会话、空态、禁用态和关闭后状态恢复；
- 页面文档宽度不得超过视口，宽表只允许局部滚动；
- 不产生未处理的控制台错误；
- 构建、类型检查、`git diff --check` 均通过；
- 参考页和实现页分别留存截图，人工检查关键间距与容器比例。
