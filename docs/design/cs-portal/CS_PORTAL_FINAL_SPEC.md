## 1. 文档使用规则

本文件是客服端跨页面实施入口：

1. 全局框架、角色名称、数据范围、页面职责和跨页面跳转以本文件为准；
2. 各页面的像素结构、字段、状态和交互以对应页面确认稿为准；
3. 如果页面确认稿与本文件出现新的冲突，先回到方案讨论，不在实施时自行选择；
4. 参考 HTML 只提供视觉和交互基线，正式数据、权限、接口和状态必须来自项目真实能力；
5. 工作台已经确认不调整主体指标，“信息评审”和“翻译待审”继续作为明确例外保留。

```text

│ 客服端版本           │                                                       │
└──────────────────────┴───────────────────────────────────────────────────────┘
```

统一规则：

- 左侧栏固定 `236px`，使用参考客服端的深靛蓝背景和斜线纹理；
- 顶栏固定 `56px`，所有端内页面保持相同控件顺序；
- 顶栏不重复显示当前账号，账号信息保留在左侧栏账号区；
- 点击左侧栏账号区：客服经理进入团队设置，其他岗位进入个人回复和通知偏好；
- “＋ 新建订单”只冻结按钮入口和名称，不附带数量，内部功能本轮未重新设计；
- 通知中心、帮助中心和搜索结果没有侧栏菜单项，通过顶栏进入；
- 完整帮助、通知和搜索结果打开后，侧栏保持进入前的业务菜单激活状态；
- 所有 Badge 和数量必须来自真实接口，不使用参考原型静态数字。

## 4. 标准角色名称

客服端和关联文档统一使用以下名称：

1. 客服经理；
2. 高级客服；
3. 普通客服；
4. 翻译人员；
5. 系统管理员；
6. 生产人员；
7. 医生/客户。

不再使用“客服管理者”“普通客服专员”等同义名称。页面中泛称“客服”时，必须结合具体业务权限和客户数据范围，不表示所有客服岗位自动拥有相同权限。

## 6. 系统管理员边界

系统管理员不作为客服端日常业务岗位：

- 登录账号的创建、编辑、启用、停用、解锁和密码安全在管理端完成；
- 客服端不展示“新增客服账号”和账号安全操作；
- 客服经理可以维护医生/成员业务资料并提交账号开通申请，但不能创建登录凭据；
- 系统管理员不因管理员身份自动获得全部客户业务数据；
- 如需查看订单、账单、配送、外协或客户资料，必须同时具备明确业务授权；
- 账号停用不删除历史订单、消息、翻译、设计、账单或审计记录。

## 7. 客户数据范围

| 岗位 | 客户与业务数据范围 |
| --- | --- |
| 客服经理 | 全部客户及团队业务数据 |
| 高级客服 | 分配给自己的客户及其订单、问单和获授权专项业务 |
| 普通客服 | 自己负责的订单和问单所需数据，不进入客户管理总表 |
| 翻译人员 | 分配的翻译任务及关联订单、附件和客户答复 |
| 系统管理员 | 默认不具有客户业务数据；按额外业务授权访问 |

客户分配变化只影响后续任务与可见范围，不覆盖历史处理人和审计记录。

## 8. 统一业务术语

| 术语 | 统一含义 |
| --- | --- |
| 新订单 | 客户已经提交但尚未完成客服登记的订单 |
| 登记订单 | 记录订单进入平台、登记人和登记时间的动作，不是客服审核 |
| 已登记 | 已完成登记，进入信息审核/翻译流程 |
| 信息审核/翻译 | 翻译人员负责的订单级文字审核、翻译和生产信息整理 |
| 问单沟通 | 客服与客户围绕订单事项进行的自由会话区 |
| 设计稿管理 | 设计文件、版本、版本执行信息和客服内部设计审核 |
| 设计确认 | 问单类型，不是独立菜单或页面 |
| 通知已读 | 用户已经查看通知，不表示业务已经处理 |
| 月结账单 | 系统按已确认规则自动汇总生成，随后由授权客服核对和发送 |

工作台中的“信息评审”和“翻译待审”保持此前确认的指标名称，不跟随菜单合并改动。

## 9. 订单信息分层

为避免无痕覆盖和页面职责冲突，订单相关信息按以下层次保存：

```text
客户原始下单信息（永久只读）
              ↓
信息审核/翻译
订单级翻译确认稿 + 结构化生产信息 + 生产备注
              ↓
存在设计稿时
设计稿管理保存“当前设计版本执行信息”
              ↓
问单沟通完成客户设计确认
              ↓
生产端执行与专业审核
```

规则：

- 信息审核/翻译维护订单级业务基线；
- 设计稿管理只维护具体设计版本的调整值；
- 没有设计稿的订单直接使用订单级确认信息；
- 客户原文、订单级确认值和设计版本值必须并存；
- 页面存在差异时显示来源、修改人、时间和原因，不允许互相静默覆盖。

## 10. 核心页面跳转

| 来源 | 事项 | 去向 |
| --- | --- | --- |
| 工作台 | 点击待处理指标或关注事项 | 对应业务页面及筛选结果 |
| 订单管理 | 登记完成 | 信息审核/翻译任务 |
| 信息审核/翻译 | 发现客户疑点 | 创建问单事项，客服在问单沟通处理 |
| 设计稿管理 | 审核通过并发起确认 | 创建设计确认问单 |
| 问单沟通 | 客户回复翻译疑点 | 信息审核/翻译进入待二次确认 |
| 问单沟通 | 客户确认或驳回设计 | 回写设计稿版本状态 |
| 订单/客户管理 | 查看账单、配送或外协 | 对应独立业务页面 |
| 通知/搜索 | 点击具体结果 | 定位目标页面、记录、页签或会话 |

跳转目标必须重新校验权限；关闭详情或返回时恢复原页面筛选、选中项和滚动位置。

## 11. 全局实施约束

- 本轮方案已确认并进入前端实施；尚缺的后端权限、任务模型和写入能力不得由静态前端伪造；
- 不修改登录、端口选择和账号认证页面；
- 不复制参考 HTML 的演示姓名、客户、订单、金额、日期、数量或 `localStorage` 状态；
- 不使用前端静态数组冒充真实业务数据；
- 不通过前端隐藏代替后端权限和数据范围；
- 不允许客服越过翻译人员完成信息审核；
- 不允许客服越过生产审核直接发布生产；
- 不允许客服代替客户确认设计稿；
- 不允许普通客服或翻译人员访问账单、产品、配送、外协或客户管理总表；
- 不允许系统管理员仅凭管理员身份读取全部客户业务数据；
- 所有客户原文、版本、沟通、状态变更和高风险操作必须保留审计记录。

## 12. 仍未完成的共同能力缺口

1. 当前只有顶层 `CS` 角色，需要补充岗位或专项权限；
2. 当前缺少统一客户分配与跨订单、消息、账单、配送、外协、搜索、导出的数据范围；
3. 前端已统一为“新订单 → 已登记 → 信息审核/翻译”，后端仍缺少登记人、登记时间、登记备注、登记幂等和独立状态事实；
4. 当前翻译、资料检查和生产备注仍主要授权给 `CS / ADMIN`，需要转给翻译岗位并补任务负责人、状态、版本和审计；
5. 当前客服账号管理、客户分配、常用回复和通知偏好仍缺少完整接口；
6. 当前医生/成员业务资料、账号开通申请与管理端登录账号之间缺少联动；
7. 当前搜索、通知、附件和导出仍需要补齐与目标页面一致的统一后端权限校验与分页；
8. 仍需完成四种客服岗位越权测试、医生端脱敏回归和完整跨端主链验收。
