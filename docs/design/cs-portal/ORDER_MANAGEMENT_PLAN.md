## 1. 页面定位

订单管理是客服查看、登记和跟踪职责范围内全部订单的总入口。页面沿用参考客服端的“快捷筛选 + 订单表格 + 右侧详情抽屉”结构，同时落实已确认的新订单登记口径。

页面不负责翻译、生产专业审核、设计稿版本管理、账单处理或完整会话交流，这些事项只显示状态和对应页面入口。

## 2. “新订单”的两个入口

| 位置 | 显示 | 含义 |
| --- | --- | --- |
| 全局顶栏 | `＋ 新建订单` | 参考文件中的全局操作入口，不显示数量；本轮不调整其内部功能 |
| 订单管理筛选 | `新订单 5` | 尚未完成系统登记的新订单队列；数字是实时数量 |

两者名称相近但作用不同，不能把筛选数量写进顶栏按钮。

## 4. 快捷筛选

| 筛选 | 口径 |
| --- | --- |
| 全部订单 | 当前客服数据范围内的全部订单 |
| 新订单 | 客户已经提交但客服尚未完成系统登记 |
| 已登记 | 已记录登记人和登记时间的订单 |
| 资料待补 | 后续信息处理识别出资料缺失且尚未解决的订单 |
| 异常订单 | 逾期、返工、投诉或其他需要客服关注的订单 |

“资料待补”和“异常订单”可以与“已登记”重叠；它们是业务关注筛选，不是互斥的订单主状态。

## 5. 登记口径

| 词句 | 含义 | 页面表现 |
| --- | --- | --- |
| 新订单 | 客户已提交、尚未完成客服登记 | 状态标签“新订单”，显示“登记订单”按钮 |
| 登记订单 | 客服确认订单已进入平台，并记录经手人和时间 | 操作按钮 |
| 已登记 | 登记动作已完成 | 状态标签“已登记”，后续进入信息审核/翻译 |

登记订单只表示订单已经进入系统并由客服记录，不表示资料完整、翻译完成、生产审核通过或已经开始生产。

登记动作需要：

- 记录登记人和登记时间；
- 默认使用当前客服作为经手人，客服经理可按权限调整负责人；
- 可填写内部登记备注，但不能修改客户原始指示；
- 重复点击必须幂等，已登记订单不得再次登记；
- 成功后刷新列表状态并创建或唤醒对应的信息审核/翻译任务。

## 6. 列表排序与颜色

默认排序规则：

1. 新订单固定排在已登记订单之前；
2. 新订单内部按客户提交时间从新到旧；
3. 已登记订单按最近更新时间从新到旧；
4. 用户主动选择其他排序方式后，以用户选择为准；
5. 分页和导出使用相同筛选与排序口径。

颜色规则：

- 新订单使用淡黄色背景和左侧强调色条；
- 登记成功后恢复普通白色行；
- 加急、临期、逾期、资料待补和异常使用独立标签；
- 不以整行红色表示普通新订单，避免与业务异常混淆；
- 颜色之外必须同时展示文字标签，不能只依赖颜色传达状态。

## 7. 表格字段

| 字段 | 展示规则 |
| --- | --- |
| 订单号 / 提交时间 | 订单号为主信息，提交时间为次信息 |
| 诊所 / 医生 | 展示当前业务归属 |
| 患者 | 按客服权限展示；导出遵循相同脱敏规则 |
| 产品 | 产品名称为主，可补充牙位和颜色摘要 |
| 登记状态 | 只显示“新订单”或“已登记” |
| 信息状态 | 待翻译审核、处理中、资料待补、等待客户回复、已完成等 |
| 当前阶段 | 展示订单主流程所处阶段，不提供客服越权操作 |
| 交付日期 | 临期或逾期时增加文字和颜色提示 |
| 订单金额 | 按账单查看权限显示；无权限时隐藏整列，不用掩码占位 |
| 负责人 | 当前负责客服 |
| 操作 | 新订单显示“登记订单”；其他订单显示“查看”，按事项补充“问单” |

页面支持客户、产品、阶段、日期和负责人等结构化筛选；搜索支持订单号、允许查看的患者名称、诊所和医生。搜索和导出都必须遵循客服客户分配范围。

## 9. 页面跳转关系

| 事项 | 目标页面 |
| --- | --- |
| 登记完成后的信息处理 | 信息审核/翻译 |
| 缺资料、客户疑点或客户回复 | 问单沟通 |
| 设计文件和内部设计审核 | 设计稿管理 |
| 账单明细和付款状态 | 账单管理 |
| 配送和物流跟踪 | 配送管理 |
| 外发生产事项 | 外协管理 |

详情抽屉只显示关联问单摘要和“进入问单沟通”入口，不重复制作自由聊天区。

## 10. 权限与数据范围

| 角色 | 页面权限 |
| --- | --- |
| 普通客服 | 查看负责客户订单、登记新订单、进入相关业务页面 |
| 高级客服 | 查看分配给自己的客户订单、登记或按权限处理和导出 |
| 客服经理 | 查看全部客户及团队订单、登记或分配负责人、按权限导出 |
| 翻译人员 | 默认不进入订单管理；从信息审核/翻译查看任务所需订单信息 |
| 系统管理员 | 不因系统管理身份自动获得全部客户业务数据；需具备对应业务权限 |

列表、统计数量、详情、附件、登记、搜索和导出必须执行一致的数据范围校验。前端隐藏按钮不能代替服务端权限控制。

## 12. 当前项目缺口

实施前需要补齐或校准：

1. 当前 `待客服初审` 状态和操作仍与“客服不审单”的确认职责冲突；
2. 目前缺少独立的“新订单 / 已登记”状态、登记人、登记时间和登记备注；
3. 需要建立登记动作与信息审核/翻译任务之间的可靠关联；
4. 当前列表和详情需要拆分登记状态、信息状态和订单主阶段；
5. 需要实现新订单优先排序及行级视觉状态；
6. 当前内联详情结构需要按参考文件改为 `540px` 右侧抽屉；
7. 导出、统计和搜索必须补齐与列表一致的数据范围校验。

## 13. 实施与验收边界

- 页面业务方案已经冻结，当前只执行前端 HTML 像素校准；未完成后端登记与权限能力继续保留为缺口；
- 不复制参考 HTML 的演示数据、金额或 `localStorage` 行为；
- 不允许登记动作变成客服业务审核；
- 不允许客服无痕修改客户原始下单内容；
- 不允许详情抽屉直接绕过翻译或生产审核发布至生产；
- 实施后验证全部筛选、默认排序、分页、搜索、抽屉、登记幂等、问单跳转、权限和导出；
- 在 `1440×900` 下保存全部订单、新订单高亮、已登记、详情抽屉和无权限状态截图。
