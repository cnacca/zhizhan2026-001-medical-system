# 客服端外协管理页面重构确认稿

> 状态：业务方案已确认；前端功能重构、HTML像素校准及真实浏览器验收已完成；后端能力仍有缺口
> 确认日期：2026-07-18
> 视觉参考：客服端筛选、表格和详情抽屉；生产端 `Cloud Data Centre` 的合作工厂选择和外协跟踪结构

## 1. 设计结论

外协管理定位为已批准外协事项的基础登记、外发去向选择、履约进度和异常跟进页面，不是供应商平台、自动派单系统或完整成本结算系统。

确认采用以下方案：

1. 外协决定由生产负责人或有业务授权的负责人作出，客服不能自行改变生产安排；
2. 客服端负责登记和跟进已经批准的外协事项；
3. 新增“外发地点”和“合作方”两个独立字段；
4. 登记外协时从已配置的外发地点/合作方选项中选择，不只使用自由文本供应商名称；
5. 列表、筛选和详情都要直接体现该批次外发到了哪个地点、哪家合作方；
6. 同一外发地点可以配置多个合作方；
7. 外协成本、供应商结算和付款不在本页处理；
8. 不显示虚构的云端实时同步、合作方在线率、产能或自动文件传输。

## 2. 依据与参考边界

项目一期范围明确要求客服端外协管理只提供基础登记和状态跟进，完整成本核算另行评估。

客服端参考 HTML 没有一对一的外协页面，因此页面整体继续使用客服端的快捷筛选、紧凑表格、语义状态和右侧详情抽屉；外发去向选择参考生产端 `Cloud Data Centre` 的 Partner Sites 卡片。

生产端参考原型还展示云端同步、合作工厂产能、外部聊天、收到其他工厂请求和自动文件传输，但当前项目没有这些真实能力，不直接搬到客服端。

## 3. 职责流程

```text
生产负责人/业务负责人
决定某个订单或部件需要外协
          ↓
形成外协批准来源
          ↓
授权客服
登记外协批次、外发地点、合作方、数量和返回期限
          ↓
授权客服
跟进合作方确认、处理进度、延期和异常
          ↓
外协件返回
          ↓
生产端
检查返回结果并继续生产
```

客服保存外协登记不等于系统已经通过接口向合作方发送订单。当前只保存内部业务事实。

## 5. 外发地点与合作方

### 5.1 数据关系

“外发地点”和“合作方”不能合并为一个自由文本字段。

```text
外发地点：广州
├── 合作方：南方精密支架中心
└── 合作方：广州数字义齿中心

外发地点：香港
└── 合作方：PartnerLab HK
```

列表统一显示为“地点 · 合作方”，例如“广州 · 南方精密支架中心”。

### 5.2 外发选项卡

登记外协时展示已配置的外发地点和合作方卡片：

```text
┌──────────────────────────────────────────────────────────────┐
│ 2 · 选择外发去向                                             │
│                                                              │
│ ┌────────────────┐ ┌────────────────┐ ┌────────────────┐   │
│ │ 🏭 广州        │ │ 🏭 上海        │ │ 🌐 香港        │   │
│ │ 南方精密中心   │ │ 华东制造中心   │ │ PartnerLab HK  │   │
│ │ 金属支架加工   │ │ 数字化加工     │ │ 复杂种植设计   │   │
│ └────────────────┘ └────────────────┘ └────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

选中后自动带出：

- 外发地点；
- 合作方名称；
- 联系人和联系方式；
- 外发地址；
- 擅长加工范围；
- 默认预计处理周期；
- 当前启用状态。

选项必须来自真实配置，不在正式环境写死演示地点。实施前需要客户提供真实的“外发地点＋合作方”清单。

## 8. 状态口径

履约状态和风险状态分开维护：

| 类型 | 状态 | 含义 |
| --- | --- | --- |
| 履约状态 | 等待外协方确认、外协处理中、待返回、已返回、已关闭、已取消 | 外协事项的业务进度 |
| 风险状态 | 正常、可能延期、已超时、外协异常、已解决 | 履约风险与异常处理进度 |

“已超时”根据当前时间、预计返回时间和实际返回时间计算，不作为客服手工选择的主状态。“已解决”表示异常处理完成，不代表外协件已返回。

## 9. 异常跟进

异常记录至少包含：

- 异常类型：延期、质量问题、数量不符、资料缺失、合作方无法处理、丢失或其他；
- 异常说明；
- 发生时间；
- 合作方反馈；
- 下一次跟进时间；
- 负责人；
- 解决结果。

```text
发现外协异常
      ↓
记录异常事实、外发地点、合作方和负责人
      ↓
跟进合作方并记录结果
      ↓
影响客户交期或要求 ──→ 问单沟通
      ↓
问题解决后标记“已解决”
```

外协异常默认是内部事项。只有影响交期或客户要求时，才从外协详情进入对应订单的问单会话。

## 10. 明确不做的功能

- 不显示没有真实连接依据的“云端实时同步”；
- 不显示未经真实数据支持的合作方在线率和实时产能；
- 不做合作方登录账号或外部聊天系统；
- 不做“收到其他工厂的外协请求”；
- 不自动把订单文件传输到外部系统；
- 不允许批量召回外协订单；
- 不在本页维护外协成本、付款和结算；
- 不允许客服通过外协登记直接修改生产工序完成状态；
- 不提供地图，除非客户后续明确提出地理可视化需求。

## 11. 权限边界

| 角色 | 页面与数据范围 | 权限 |
| --- | --- | --- |
| 客服经理 | 全部外协记录 | 登记和跟进已批准外协事项 |
| 获得外协权限的高级客服 | 分配给自己的订单或客户 | 按授权登记和跟进外协 |
| 普通客服 | 默认不可见 | 只在订单详情查看必要外协摘要 |
| 翻译人员 | 不可见 | 无外协权限 |
| 管理员 | 只读外协总览 | 查看履约和异常，不登记或更新 |
| 生产负责人 | 生产端 | 提出/批准外协并检查返回结果 |
| 生产人员 | 与本人任务相关 | 查看必要外协结果，不维护客服跟进 |
| 医生/客户 | 不可见内部外协 | 只查看脱敏后的订单外部进度 |

医生端不能看到具体合作方、内部外协原因、外协成本、异常责任或内部跟进记录。

## 12. 页面联动

| 外协操作 | 去向/结果 |
| --- | --- |
| 查看订单 | 进入内部订单详情 |
| 批准来源 | 读取生产负责人或业务负责人批准记录 |
| 影响客户交期 | 进入对应订单的问单沟通 |
| 外协件返回 | 通知生产端进行返回检查 |
| 外协成本 | 进入生产成本/财务相关页面，不在客服页编辑 |
| 合作方资料 | 读取外发地点与合作方配置，不在批次详情随意改名 |

## 13. 当前系统已实现能力

当前项目已有：

- `production_outsourcing_batch` 外协批次表；
- 关联订单、外协内容、合作方名称、数量；
- 发出时间、预计返回和实际返回时间；
- 简化履约状态和异常说明；
- 根据预计返回时间计算是否超时；
- 内部角色查询外协列表和详情。

这些能力应在后续重构中复用，但目前主要是只读基础。

## 14. 当前系统缺口与后续实施项

以下缺口已记录，但不在当前方案讨论阶段实施：

1. 当前没有外发地点和合作方基础档案，也没有一个地点对应多个合作方的数据关系；
2. 当前 `supplier_name` 是批次自由文本，不能形成稳定的外发选项和筛选；
3. 当前没有外协登记、状态更新、实际返回和取消接口；
4. 当前没有外协批准来源、负责人和客户数据范围字段；
5. 当前只有 `SENT / DELAYED / RETURNED` 等简化状态，没有目标履约状态与风险状态拆分；
6. 当前没有独立进度事件和异常跟进记录；
7. 当前没有外协返回后的生产检查联动；
8. 当前没有合作方启停、联系人、地址、擅长范围和默认周期配置；
9. 当前没有医生端内部外协信息的专门投影与脱敏验收；
10. 当前客服外协菜单错误复用生产成本管理页，不能承担外协履约业务；
11. 当前外协查询允许 ADMIN、CS、WORKER，但没有目标岗位权限和客户/订单数据范围；
12. 当前没有管理员只读、生产负责人批准、授权客服登记和普通客服不可见的完整权限体系；
13. 客户尚未提供真实“外发地点＋合作方”清单，实施时必须使用真实配置，不使用演示地点作为正式数据。

## 15. 实施边界

- 外协管理业务方案已经冻结，当前只执行前端 HTML 像素校准；真实地点、合作方和写入接口仍作为后端/数据缺口；
- 外协决定、批准来源和客服登记职责必须在实现前保持分离；
- 外发地点与合作方必须使用稳定标识关联，不能继续只保存可随意修改的名称；
- 外协批次、进度、异常和操作记录不得物理删除；
- 实施后需覆盖登记、地点选择、合作方筛选、超时计算、异常跟进、返回联动、权限和医生端脱敏；
- 合作方账号、实时网络、文件自动发送、成本结算或供应商门户如需开发，必须另行确认范围。
