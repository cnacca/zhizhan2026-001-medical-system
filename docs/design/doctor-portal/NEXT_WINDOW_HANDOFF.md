## 3. 角色与权限口径

- 多角色用户登录后必须选择当前诊所身份；本轮顶部身份选择器已实现。
- 切换身份后重新加载该角色的数据与动作范围，权限不叠加。
- 医生默认 `SELF`；诊所管理员与前台默认 `CLINIC`；护士默认 `ASSIGNED`。
- 只有医生身份且订单返回 `APPROVE_REVIEW` / `REJECT_REVIEW` 动作时，才能操作确认。
- 账单权限和物流权限独立；只有诊所管理员可维护诊所成员。

前端已在请求中携带 `X-Clinic-Role`，用于后端补齐当前身份隔离。后端必须签发或解析与当前入口 / 当前诊所角色一致的身份上下文，不能继续使用多角色权限并集。

## 5. 本轮浏览器验收

验收环境：`http://127.0.0.1:15173/?doctorMock=1`，视口 `1440 × 900`。

已完成的真人式点击路径：

1. 医生入口登录，验证不预填账号密码、不显示医生端快速登录。
2. 工作台确认六项概览、双栏待办 / 交付和趋势区；确认 230 / 56 壳层。
3. 订单搜索和字段列验证；确认订单页及详情抽屉无物流公司、承运商、运单号。
4. 全屏六步下单：选择患者和产品、填写病例、填写后台动态字段、上传 STL、选择三类确认项、复核并提交。
5. 提交后重新打开新订单详情；验证 STL 文件和三类确认记录均存在。
6. 设计稿多版本预览、同意二次确认、驳回必填门禁；同意后订单列表待办同步清除。
7. 消息搜索覆盖历史正文，全部 / 未读 / 已读筛选，发送消息。
8. 患者新建、列表出现、详情抽屉再次打开。
9. 账单四标签、物流详情、确认收货二次确认。
10. 多角色切换：诊所管理员不显示订单助手、新建订单和医生确认动作；切回医生后恢复。
11. 全局搜索、通知搜索和已读 / 未读筛选、订单助手安全拒答。
12. 修复后重新登录并复查浏览器控制台：新增 error `0`、新增 warning `0`。

本轮浏览器验收中发现并已修复：

- 消息搜索后右侧仍停留在旧会话。
- 新订单提交后能出现在列表，但详情不存在。
- 设计稿确认后列表仍显示“待确认”。
- 六步流程草稿保存失败仍会进入下一步。
- “搜索患者”输入框没有筛选作用。
- 文件只生成本地 ID，真实提交时会被过滤掉。
- 新建患者只改本地列表，随后无法打开详情。
- 角色切换只改变按钮外观，没有重新加载角色范围。

## 6. 后端待补合同

页面组件不需要重构；后端补齐时应以 `DoctorGateway` 合同为准，完成 API 适配：

- 当前诊所角色激活、角色专属 Token 或等价服务端身份上下文；实现 `SELF / CLINIC / ASSIGNED` 数据范围。
- 医生安全订单列表和详情投影，服务端白名单剔除内部字段。
- 医生可见产品目录、价格、动态表单字段和三类 `review_capabilities`。
- 通用三类确认接口：多版本、状态版本、幂等键、同意 / 驳回、驳回意见必填。
- 订单线程、历史消息搜索、会话已读持久化。
- 按单账单、月结账单、发票、退款、物流、确认收货。
- 诊所成员与角色、账单权限、物流权限、当前身份切换。
- 医生通知安全投影，按当前角色 / 入口过滤 audience；不能只按用户 ID 返回全部通知。
- 订单提交保存 `product_id`、`review_options` 和已经上传完成的 `file_ids`。

当前前端的第二道防线会递归拒绝含内部字段的订单响应，并过滤疑似内部通知；这不能替代服务端安全投影。多角色 Token 隔离和通知 audience 隔离仍是上线阻塞项。
