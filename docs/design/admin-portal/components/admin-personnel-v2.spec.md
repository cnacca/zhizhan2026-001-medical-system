# 管理端人员管理 V2 组件规格

> 状态：`CONFIRMED_AND_FROZEN`
> 用户确认：2026-07-16
> 总规格：[管理端前端不可偏离实施规格](../IMPLEMENTATION_BASELINE.md)
> 可交互参考：`../reference/personnel-management-v2-concept.html`
> 固定截图：`../reference/personnel-management-v2-1440x900.png`

## 1. 页面骨架

- 侧栏固定 `230px`，顶栏固定 `56px`；
- 主内容内边距 `19px 24px 22px`；
- 页头高 `58px`，不显示指标卡；
- 主工作卡高 `calc(100vh - 155px)`，`1440×900` 下约 `745px`；
- 主工作卡两列：左侧组织区 `218px`，右侧人员区占余下宽度；
- 工作卡使用白色背景、`1.5px #e2e8f0` 边框、`14px` 圆角和轻阴影。

## 2. 页头

- 眉标“人员与职责”，主标题“人员管理”；
- 说明“查找公司人员，维护账号、部门岗位和可管理范围。”；
- 右侧仅保留次按钮“部门与岗位”和主按钮“新增人员”；
- 不显示导出按钮，除非后续已有真实导出能力且用户明确要求加入。

## 3. 左侧组织区

- 标题“人员范围”，右侧显示真实总人数；
- 第一组固定为“全部人员 / 管理人员 / 普通员工”；
- 第二组按真实部门动态显示；
- 每项高 `35px`，显示名称与真实人数，激活态使用管理蓝浅底；
- 底部只显示当前操作者适用的管理范围说明，不展示技术权限码；
- 点击组织项立即过滤右侧列表，不切路由、不打开新页。

## 4. 人员工具栏与表格

- 工具栏最小高 `60px`；
- 搜索框宽 `260px`，即时匹配姓名、账号、部门和岗位；
- 仅保留“人员级别”和“账号状态”两个下拉筛选；
- 表格列固定为：人员、部门/岗位、人员级别、管理范围、账号状态、当前任务、操作；
- 表头高 `38px`，数据行最小高 `62px`；
- `1440×900` 和 `1280×800` 首屏均应完整显示至少 7 行候选稿数据区域；真实数据不足时显示真实空状态；
- 行操作只显示“查看 / 编辑”，点击整行也打开同一人员抽屉；
- 账号状态使用语义色和文字，不仅依赖颜色；
- 管理范围必须使用用户语言，例如“客服部 / 可设置主管、普通员工”或“无管理职责 / 仅处理自己的任务”。

## 5. 人员抽屉

- 抽屉宽 `430px`，从右侧进入；遮罩 `rgba(15,23,42,.28)`；
- 内容顺序固定为：账号资料、组织归属、职责权限、账号状态；
- 新增人员默认普通员工；编辑时展示当前真实级别与范围；
- 职责区只展示当前操作者能分配的级别和管理范围，不可分配项不进入可选列表；
- 经理、主管保存能力尚未接通时，相关控件必须禁用并给出中文说明；
- 关闭按钮、取消、遮罩和 `Esc` 均可关闭；
- 保存中禁止重复提交；成功后刷新人员与列表；失败不显示原始接口错误。

## 6. 部门与岗位弹窗

- 从页头“部门与岗位”进入，不恢复“组织岗位”页签；
- 候选稿宽 `640px`、高 `470px`；左侧部门列表，右侧岗位列表；
- 只显示真实组织与岗位；新增、编辑、停用能力必须以真实后端接口和当前操作者权限为准；
- 没有真实写能力时只能只读，不显示虚假保存成功。

## 7. 响应式与可访问性

- `1440×900` 为像素基准；`1280×800` 必须无页面级横向溢出；
- 宽表仅在人员内容区内部滚动；
- `<=980px` 可把组织区改为顶部范围选择器，但不得改变信息结构；
- 所有可操作元素具备 hover、`focus-visible`、disabled 和 loading 状态；
- `prefers-reduced-motion: reduce` 时关闭非必要过渡。

## 8. 禁止项

- 不显示四张顶部人员指标卡；
- 不显示人员管理三页签；
- 不常驻展示完整四级权限关系带；
- 不恢复独立账号权限、用户管理或角色权限菜单；
- 不伪造最近登录、人数、管理范围、保存成功或经理/主管权限数据；
- 不把医生和诊所账号混入本页。
