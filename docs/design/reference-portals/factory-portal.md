> 权威源：[factory-portal.html](../../../frontend/public/reference/factory-portal.html)
> SHA-256：`0f1544c41764bce5cb5017fc6c816b540c389dbe825ea76dd7285cfa5676c27e`
> 最近浏览器复核：2026-07-16，目标视口 `1440×900`

## 1. 定位

生产端是经理、组长和员工共用的生产运营原型。视觉身份为深蓝灰侧栏配青绿色主操作色，强调实时同步、工序队列、看板、派工、扫码、工时和审核。

生产端允许看到内部生产信息，但必须按经理、组长、员工和部门范围进行严格隔离。医生端和医生接口不能复用这些内部字段。

## 2. 核心视觉参数

| 项目 | 参考值或实测值 |
| --- | --- |
| 页面背景 | `#f7f9fc` |
| 侧栏 | `230px`，`#0c2340`，固定定位 |
| 顶栏 | `54px`，白色，吸顶 |
| 实时同步条 | `26px`，青绿色，位于主内容顶部 |
| 主操作色 | `#0d9488` |
| 正文字体 | `Plus Jakarta Sans`，基准 `14px` |
| 标题字体 | `Lora` |
| 详情抽屉 | `#drawer`，右侧固定，约 `560px`，全高 |
| 卡片阴影 | `rgba(12,35,64,.06) 0 1px 3px` |

2026-07-16 实测 `1440×900` 时，滚动条约占 `4px`；页面计算宽度约 `1436px`，主内容区约 `1206px`。

## 3. 实体页面

| 页面 ID | 用途 |
| --- | --- |
| `page-dashboard` | 生产总览、异常、待发货、医生审核和部门负载 |
| `page-orders` | 生产订单、筛选、派工和阶段操作 |
| `page-kanban` | 按日期和工序队列组织的生产看板 |
| `page-workorders` | 工单列表、批量选择和打印 |
| `page-staff` | 员工、部门、负载和编辑 |
| `page-scan` | 扫码/录入、操作人切换和检入反馈 |
| `page-messages` | 生产沟通 |
| `page-datacenter` | 云端订单协作、发送、撤回、聊天和追踪 |
| `page-workstation` | 组长/员工工作站、派工、个人统计和审核的复用容器 |

`lead_assign`、`lead_stats`、`my_stats` 是虚拟导航状态，实际复用 `page-workstation` 动态渲染。

## 4. 角色与菜单模型

| 角色 | 账号规模 | 默认入口 | 主要菜单与范围 |
| --- | ---: | --- | --- |
| Manager | 1 | Dashboard | 全局 Dashboard、Orders、Kanban、Work Orders、Staff、Scan、Messages、Cloud Data Centre |
| Lead | 4 | Workstation | 部门订单/看板/工单、派工、部门统计、团队、个人工作站、消息 |
| Staff | 7 | Workstation | 仅个人工作站、个人绩效和消息 |

组长按自己的 `queues` 查看部门订单和列；员工只看明确分配给自己的订单。正式实现必须由后端同时限制查询、详情、派工、审批、工时和导出。

## 5. 生产视觉与状态表达

- 实时同步条必须明确同步状态和需要客服/医生处理的事项。
- 看板按工序列组织卡片，卡片展示订单、产品、客户/患者代码、标签、技师和耗时。
- 加急、超时、跨日 carry-over、待审核、未分配使用不同色彩和徽标。
- 生产详情抽屉使用客户代码和患者代码，顶部明确“生产视图不显示财务信息”。
- 工序时间线同时展示英文、中文、完成/进行中/待处理和跳过状态。
- 部门容量通过进度条和占用比例表达；表格和卡片 hover 保持低幅度反馈。

## 6. 必须保留的交互

1. 经理、四类组长和七类员工账号切换。
2. 角色切换后菜单、默认入口、订单范围和操作按钮同步变化。
3. Production Orders 的搜索、快捷筛选、选择、技师变更和详情。
4. Kanban 的上一天、下一天、Today、日期选择、carry-over 与卡片详情。
5. Work Orders 的选择、单张打印和批量打印。
6. 组长派工、容量提示、确认分配和团队统计。
7. 员工 Start Work、Done、超时判断；组长 Approve / Reject。
8. CAD 文件下载、3D Viewer、回传上传、发送设计给客服和修改后重发。
9. Scan & Check-in 的操作人切换、扫码和结果反馈。
10. Messages 与 Cloud Data Centre 的筛选、聊天、发送、撤回和追踪。
11. 语言切换、Toast、Modal、遮罩关闭和打印样式。

源码中约有 `153` 个内联 `onclick`。生产端的“开始工作—完成—组长审核”是完整状态链，不能拆成互不关联的视觉按钮。

## 7. 响应式边界

生产端没有屏幕宽度媒体查询，仅定义打印样式。当前像素级基准是桌面 `1440×900`。

如需移动或平板端，必须另做信息架构和交互设计；尤其是多列看板、详情抽屉、批量选择和打印，不应简单缩放。

- Scan & Check-in；

- Staff 的个人工作站、开始/完成和个人统计；
