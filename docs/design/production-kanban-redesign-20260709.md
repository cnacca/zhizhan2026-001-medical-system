# Production Kanban Redesign 2026-07-09

状态：design-approved-for-review / NOT_IMPLEMENTED。

本文件记录生产端 `/production/board` 生产看板重设计规格。目标是借鉴 WeChat 附件 `factory-portal.html` 中 Kanban Board 的横向工序队列、高密度卡片、SLA 和风险表达方式，但实现仍遵循当前 Vue3 + Element Plus 前端架构。

## 范围

### 本次范围

- 只重设计生产端 `/production/board`。
- 不替换 `/dashboard` 生产仪表盘首页。
- 外层继续保持当前系统壳、导航、页面容器和 Element Plus 控件语气。
- Kanban 工作区采用参考 HTML 的紧凑生产看板形态。
- 详情能力保留，但从常驻右侧面板改为点击卡片后打开覆盖式抽屉。

### 非目标

- 不改后端接口。
- 不新增权限或角色视图逻辑。
- 不做拖拽换列。
- 不做自动轮询刷新。
- 不展示新增敏感信息。
- 不把已发货、已完成历史订单默认塞进主看板。

## 参考页面要点

参考 HTML 的 Kanban Board 具有以下特征：

- 横向超宽工序队列，参考为 13 个 production queues。
- 列头显示工序名称、中文说明、SLA、订单数和 carry-over 数。
- 卡片高密度展示订单号、产品、客户/患者代号、牙位、负责人、耗时。
- 超时、carry-over、加急等风险通过颜色、标签、进度条表达。
- 顶部有日期切换、Today、超时汇总和队列汇总条。

本项目不直接复制英文文案和静态数据，只复用信息结构、视觉层级和交互模型。

## 页面结构

新版 `/production/board` 自上而下分为四块：

1. 页面标题区：标题仍为“生产看板”，展示当前活跃订单数和最后更新时间。
2. 看板控制区第一行：日期切换、Today、超时汇总、最后同步提示。
3. 看板控制区第二行：状态筛选、关键词搜索、刷新/查询按钮。
4. Kanban 主工作区：辅助列 + 真实工序列 + 辅助列，横向滚动。

当前 `prototypeQueueChips` 保留，但降级为顶部看板摘要 chips，展示异常、待问、返工、终检待发等关键数字。点击 chip 可以沿用现有筛选语义，不再作为页面主视觉。

## Kanban 列模型

### 主列维度

主看板按工序队列组织，不再以当前 7 个订单状态列作为主要视觉结构。

列来源优先级：

1. 批量读取订单工序实例后，从 `nodes` 中找当前 `READY` 或 `IN_PROGRESS` 节点。
2. 以节点 `step_order` 决定工序列顺序。
3. 以 `node_code` / `process_name` 合并同类列。
4. 无法匹配工序实例时进入辅助列。

列标题以中文为主；节点代码或英文名只作为小字辅助，例如：

```text
数据审核
SLA 120 分钟 / DATA_REVIEW
```

### 辅助列

非具体工序状态不硬塞进工序列，使用辅助列承接。

左侧辅助列：

- 待生产审核
- 待派工 / 工序待生成
- 工序待同步

中间主列：

- 来自真实 `step_order`、`node_code`、`process_name` 的工序队列。

右侧辅助列：

- 医生待确认
- 终检待发

已发货、已完成默认不展示在主看板中，但可以通过状态筛选查看。

### 空列

空工序列保留，不隐藏。空态显示轻量文案，例如：

```text
✓ 暂无积压
```

## 数据策略

### 不改后端

第一版不新增后端 API。继续复用现有能力：

- `/orders` 加载订单列表。
- `/orders/{id}/process-instance` 读取单个订单工序实例。
- `/orders/{id}/logistics` 保留终检发货能力。

### 渐进工序同步

加载流程：

1. 先加载 `/orders`，最多按当前页面上限 50 单参与看板。
2. 先渲染基础订单卡，避免页面空等。
3. 低并发批量读取可见订单的工序实例。
4. 成功后把订单移动到真实工序列。
5. 失败、超时或尚未生成工序的订单进入“工序待同步”或对应辅助列。

加载状态分两层：

- 订单列表加载：显示整页轻量加载态。
- 工序详情同步：卡片显示同步中、待同步或同步失败小标签。

### 日期控制

顶部日期切换要保留参考形态：

- 前一天
- 日期输入
- 后一天
- Today
- 超时汇总

如果现有接口没有日期过滤能力，第一版只把日期作为看板视图状态和提示，不伪装成真实后端筛选。

### 刷新策略

第一版只做手动刷新，不做自动轮询。刷新后更新最后同步时间。

## 卡片设计

卡片采用高密度生产现场卡，重点服务现场扫视和异常定位。

每张卡片优先展示：

- 订单号
- 产品类型
- 客户/患者代号
- 牙位
- 当前工序
- 当前负责人
- 节点状态
- SLA / 已耗时
- 风险标签
- 细进度条

SLA 和耗时规则：

- 有 `standard_duration` 时显示为 SLA。
- 有真实开始、完成或工时字段时计算已耗时。
- 推断不到耗时时显示“耗时待同步”，不编造分钟数。
- 进度条优先表达 `已耗时 / SLA`。
- 没有 SLA / 耗时数据时退回展示节点完成比例。

风险优先级从高到低：

1. 超时
2. 返工
3. 待确认
4. 加急

风险视觉采用左侧色条和小标签，不使用整张卡大面积警示色。

列内排序：

1. 风险优先级。
2. 已耗时或最后更新时间。
3. 订单号作为稳定兜底。

## 抽屉详情

点击卡片后打开覆盖式抽屉。桌面端和移动端都使用抽屉，不再使用常驻右侧详情栏。

抽屉顶部突出当前工序上下文：

- 当前工序
- 负责人
- 节点状态
- SLA / 已耗时
- 风险标签

抽屉内容分组：

1. 订单摘要：订单号、内部状态、外部状态、诊所/客户代号等当前已有生产必要字段。
2. 节点统计：待开工、进行中、已完成、跳过/待处理。
3. 节点进度：沿用当前节点列表能力。
4. 终检发货：承运商、物流单号、录入物流并发货按钮。

抽屉只保留生产必要的脱敏字段，不新增财务、完整医生信息、沟通全文等敏感信息。

## 顶部汇总条

保留类似参考 HTML 的 summary bar，放在日期行下方。

每个汇总 chip 展示：

- 工序名
- 订单数
- 超时数
- 进行中数

点击某个 chip 时横向滚动定位到对应列。第一版不做列冻结。

## 响应式

桌面和移动端都保持横向 Kanban，不折叠成纵向普通列表。

- 列宽稳定，允许横向滚动。
- 移动端压缩卡片字号、间距和抽屉宽度。
- 顶部工具条可换行，但不遮挡 Kanban。

## 验收标准

- `/production/board` 默认进入后展示活跃生产订单看板。
- 主视觉是工序队列，而不是原 7 个订单状态列。
- 非工序状态进入辅助列，工序实例成功同步后进入真实工序列。
- 点击卡片打开抽屉，抽屉能查看订单摘要、节点统计、节点进度和终检发货。
- 不改后端接口。
- 不做拖拽换列。
- 不做自动轮询。
- 已发货、已完成默认不占用主看板，可通过筛选查看。
- 空工序列保留并显示轻量空态。
- 工序同步失败的订单不消失，进入“工序待同步”辅助列。
- 卡片风险排序、风险标签和进度条可见。
- 文案以中文为主，代码或英文只作为辅助小字。

## 后续实现建议

建议下一步先写实现计划，再改代码。实现计划应至少拆成：

1. 数据归类模型：订单、工序实例、辅助列、工序列、风险和排序。
2. UI 结构迁移：顶部控制区、汇总条、Kanban 列、卡片。
3. 抽屉迁移：把现有右侧详情能力迁入抽屉。
4. 渐进同步：低并发读取工序实例和失败降级。
5. 验证：前端构建、关键交互 smoke、浏览器截图检查。
