## 1. 核心模型

```text
order_case_group（医生看到的病例订单组）
├── orders（产品子订单 1：固定修复）
│   ├── 独立客服初审 / 生产审核 / 设计 / 生产 / 质检
│   └── 独立价格快照 / 账单 / 物流 / 返工
├── orders（产品子订单 2：活动义齿）
│   ├── 独立客服初审 / 生产审核 / 设计 / 生产 / 质检
│   └── 独立价格快照 / 账单 / 物流 / 返工
└── 组级共享资料、草稿版本、提交幂等键、外部聚合状态
```

`orders` 不改名、不删除，继续是所有生产事实的根。订单组不拥有生产工序实例，也不共用审核状态。

## 2. 产品分层

```text
category
└── product（真实子订单 SKU）
    ├── variant（同一成品的配置变体）
    ├── material（制造属性，主材料默认单选）
    ├── accessory（附加选项，可多选并带数量）
    ├── tooth_rule
    ├── form_schema_version
    ├── upload_rule
    ├── workflow_mapping
    └── pricing_rule_version
```

- 配件只有在独立生产、计价、库存、发货或返工时才成为子订单。
- `Full Denture` 与 `Complete Denture` 是“全口义齿”的别名。
- `Lucitone 199` 是材料品牌/规格，不是成品 SKU。
- 牙色、牙龈色、基托色、矫治器颜色使用不同字段。

## 3. 动态表单与快照

- 字段类型：text、textarea、number、boolean、single_select、multi_select、quantity_list、tooth_selection、file_reference、object。
- 条件规则：通过 schema 中的 depends_on / operator / value 表达显示和必填条件。
- 提交时冻结：
  - product snapshot
  - schema version
  - normalized form values
  - tooth selection
  - upload requirement result
  - pricing rule version and price snapshot
- 配置停用使用 `INACTIVE`，不物理删除历史字段。

## 4. 产品配置中心

- 管理端维护分类、产品、变体/SKU、别名、材料、材料品牌/规格/语义色号、配件、绑定、动态字段、牙位、上传、价格、交期与工序映射。
- 支持新增、修改、逻辑停用、恢复、排序、复制、预览和发布；发布生成不可变版本。
- 只有从未发布且未引用的草稿允许物理删除；其余实体/绑定删除返回 409。
- 产品-材料/配件绑定保存必选、单/多选、默认值、数量上下限、适用产品/变体/牙位、价格增量、排序、状态和版本。
- `catalog:manage` 负责维护，`catalog:publish` 负责发布；所有变更记录前后值和操作者。
- 批量导入/导出至少提供稳定模板与校验接口；原始 Word 不直接入库。

## 5. 标准工时维护

- 后端/数据库保留现有九条工序链节点的标准分钟、版本、生效时间、权限和审计底座。
- 支持空值、单项/批量填写、导入、复制上一版本和停用。
- 客户尚未提供正式标准工时；数据到位前不展示管理端菜单，版本保持空值/DRAFT/INACTIVE，`WORKFLOW_STANDARD_TIME_FORMAL_ENABLED` 默认关闭并阻止发布。
- 显式启用后，工序实例化才把有效标准分钟快照到 `order_process_node.standard_duration`；后续版本不改历史实例。
- 标准工时不等于 `work_log` 实际工时；不开放普通员工手填实际工时。
- 正式开关关闭时，不生成标准截止时间/生产超时，也不计算标准工时覆盖、准时率、效率或绩效分；17/19 分钟只保留为 INACTIVE 浏览器验收证据。
- 权限为 `workflow:standard-time:manage`。
- 不开放节点增删、排序、拖拽或 DAG 编辑。

## 6. 文件模型

- 单文件上限：500MB。
- 组级：患者面像、通用影像、共享扫描/病例资料。
- 子订单级：只适用于特定产品的 STL、设计要求、照片、CBCT 或其他资料。
- 订单组总容量、文件数量和格式使用服务端配置，不在代码永久写死。
- MinIO 私有桶、服务端授权、Multipart、签名 URL 和审计继续复用。

## 7. 价格模型

```text
产品基础价
+ 材料加价
+ 配件单价 × 数量
+ 特殊工艺
+ 加急/调整费用
= 提交报价快照
```

- 规则由后端版本化。
- 未配置正式价格时返回 `PENDING_QUOTE`。
- 人工改价必须填写原因并留审计。
- 配置变更不重算已提交订单，不覆盖最终账单。

## 8. 隐形正畸

- 一期可只启用 A 型，但类型来自配置。
- 七步向导：基本信息；资料/模型；临床信息与牙位诊断；矫治器/联合矫治；目标牙位与移动策略；方案参数；预览/模板/提交。
- 方案版本、内部审核、医生确认、生产批次和阶段调整均为独立可审计事实。
- 批次保存总步数、批次号、当前起止步和数量。
- 阶段调整/后续加工新增申请、方案版本或批次，不覆盖原记录。
- 复用现有设计文件和版本确认，不引入高级 Web 3D。

## 9. 权限与门禁

- 授权生产审核员：拥有 `workflow:review-production` 直接权限，处理合法队列。
- ADMIN：查看“生产审核监控”，异常兜底必须填原因并审计。
- 普通 WORKER / CS：不能读取或执行生产审核。
- 正畸内部方案审核、医生方案确认、生产审核是三个独立门禁。
- 医生只看本人诊所/医生归属的外部投影；医生端、WebSocket 和 AI 不返回内部生产信息。
