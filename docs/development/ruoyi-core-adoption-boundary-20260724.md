# RuoYi 核心源码引入边界（2026-07-24）

## GOAL-024 历史结论

GOAL-024 当时只完成真实 RuoYi-Vue-Pro 后端核心源码引入与隔离构建基础，没有改变现有业务权限结果。后续采用方式已由 2026-07-28 的 D-171 更新为渐进桥接。

## 2026-07-28 已确认采用方式

- 保持现有业务运行时可用，逐段桥接 RuoYi 的权限、DataScope、审计和管理能力，不做一次性全面替换。
- “源码已引入并独立构建”只算技术资产，不算 RuoYi 已进入真实业务运行路径，也不能单独关闭 M2。
- 第一批先完成版本兼容、运行时边界和一个可验证的真实桥接点；每批都必须保留现有登录、Token、权限结果和回滚路径。
- 医生、客服、技工账号由超级管理员创建；组长、质检继续作为 `WORKER` 的权限点或岗位授权，不新增真实端口角色。

## 已确认事实

- 一期真实端口角色只有医生、客服、技工、超级管理员；每个端口一个真实角色。
- 经理、主管、组长、质检、仓库、诊所管理员、前台、护士等当前不是新增 RBAC 角色。
- 生产审核与派工不能授予客服。
- 经理 / 主管层级是正式业务要求，但具体权限分配尚未确认。
- 诊所内部身份当前只存在于前端设计，不作为后端真实角色。
- 账号创建权限已确认由超级管理员承担。
- 标准工时业务数据当前没有可用标准值，不能由开发人员猜测或伪造。

## 当前明确不做

- 不配置四个真实角色的菜单、按钮、接口或 DataScope。
- 不迁移现有账号、角色、权限、菜单和部门岗位数据。
- 不启用上游演示账号、演示角色、演示菜单或默认口令。
- 不替换现有 Bearer Token、refresh token 或 Controller 权限守卫。
- 不把“源码已经引入”描述为“RuoYi 已经完成业务接管”。

## 后续迁移门

1. 依赖和父 POM 版本对齐：确认现有 Spring Boot 3.5.0 与上游 3.5.15 的统一策略。
2. 数据模型映射：明确现有 `system_*` 表与上游 system/infra 表的保留、迁移或兼容视图方案。
3. 运行时桥接：逐段接入 common/web/security/mybatis/redis，不一次性替换现有主链路。
4. 账号与 Token：先定义无停机兼容和回滚方案，再迁移登录态。
5. 角色权限映射：沿用现有四角色和个体权限点，先建立兼容映射，不用上游演示角色覆盖现有授权结果。
6. 审计和管理 UI：在运行时稳定后接入，不能用上游演示数据代替一期业务规则。
