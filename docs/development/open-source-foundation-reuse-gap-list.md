# Open Source Foundation Reuse Gap List

更新日期：2026-07-04

## 目标

一期后续开发默认优先复用 RuoYi-Vue-Pro / 若依 Pro 这类开源后台底座的成熟能力，把自研精力留给牙科工厂专有业务：双状态投影、工序实例、入检出检、返工绩效、医生端脱敏、文件鉴权签名和 AI 安全读模型。

## 复用原则

- 通用后台能力优先走底座范式：用户、角色、菜单、权限码、字典、操作日志、登录日志、通用 CRUD、代码生成器和后台表单/表格页面。
- 牙科生产业务继续保留项目自研：9 条工序链、订单工序实例快照、入检/出检、返工影响、工时绩效、终检门禁、医生端外部投影和 AI-3 安全读模型。
- 新增后台维护页先判断能否套用“字典/CRUD/菜单/权限”模式，不再继续手写一套完整后台底座。
- 不引入真实密钥，不绕过鉴权，不为了复用底座而重写当前已通过验收的业务主链路。

## 当前复用现状

| 能力 | 当前实现 | 底座复用判断 | 下一步 |
| --- | --- | --- | --- |

## 本轮 9D.55 决策

返工字典后台维护采用“底座字典管理第一增量”而不是继续硬编码：

- 新增 `rework_dictionary_item` 表，表达字典类型、编码、名称、排序和状态。
- 新增 `rework:dictionary:manage` 权限和 `/system/rework-dictionaries` 管理菜单。
- ADMIN 可新增、编辑和停用返工原因 / 责任类型。
- 生产端关闭返工仍只读取 ACTIVE 字典项；停用项不能继续用于关闭返工。
- 医生端不能管理返工字典，也不能读取内部返工管理数据。

## 仍未完成

- 尚未全量接入 RuoYi-Vue-Pro 完整管理 UI、代码生成器、操作日志和登录日志。
- 设备、物料、安环、成本、奖惩仍只有只读汇总，不做录入/审批/CRUD。
- 返工字典第一增量不做批量导入、删除、审计日志、字典分组 UI 或复杂审批。
- 后续若要大规模迁移到底座，需要单独设计迁移方案，不在 Task 8 小闭环里隐性完成。
