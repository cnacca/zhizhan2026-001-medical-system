## 2026-07 新资料对齐

2026-07-01 收到新版资料：`智能下单平台_PRD_V1.0.docx`、`TRD_AI智能下单平台V1_0_1_.docx`、`API规范.yaml`。后续以这批资料作为最新业务口径，但不直接覆盖仓库当前实现和 `docs/api/openapi.yaml`。

- 新 PRD/TRD/API 是业务准绳。
- 当前仓库已经补出的 `/auth/me`、通知 REST、Multipart 断点恢复、返工接口、节点 start/complete/skip 等增量属于有效技术资产。
- OpenAPI 后续采用合并策略：新版 API 的业务口径 + 当前已实现增量。
- 原始附件来自本机微信缓存路径，不提交进仓库；如需长期保存，应先脱敏并放入稳定资料目录。

## 当前优先依据

任务拆解和技术执行口径以 2026-07 新版 PRD/TRD/API 为最新业务准绳，并保留当前仓库已验证增量。深度研究中属于实现方式、数据一致性、安全边界、测试验收的内容纳入一期；属于新增功能、复杂平台或二期演进的内容不进入一期开发。

## 源材料风险

- 本地资料包路径可能因转发、下载或开发机环境变化而失效。
- 开发前建议把确认后的 PRD、TRD、OpenAPI、生产流程整理为稳定脱敏版本。
- 不要提交包含密钥、真实客户隐私或真实医疗数据的材料。
