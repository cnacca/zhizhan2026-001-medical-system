## 培训讲师检查点

- 先说明本手册只覆盖本地第一增量，不代表完整生产操作手册已经交付。
- 演示时不得使用真实患者、真实订单、真实密钥、真实 webhook、真实服务器地址或客户隐私。
- 医生端必须只展示外部状态和医生可见资料。
- AI 只做草稿、辅助和查询，不自动审核、自动发送或自动医疗判断。
- 客户 / PM 确认项、正式培训签到和签收必须另行记录；本手册不代表客户培训签收完成。

## 通用登录入口

1. 打开前端地址。
2. 在登录页选择医生端、客服端、生产端或管理端。
3. 使用对应角色账号登录。服务端会校验账号角色与入口是否匹配，错入口登录会被拒绝。
4. 登录后先进入工作台，再从左侧菜单进入具体功能。

注意：

- 不要把本地 smoke 账号或示例密码写入客户正式手册。
- 正式环境必须关闭 `X-Bootstrap-*` 本地兼容路径。
- 医生端页面不得展示内部工序、员工、返工、工时、绩效、内部附件或内部备注。

## 医生端

### 新建订单

1. 进入医生端。
2. 打开订单管理 / 新建订单。
3. 选择产品类型，填写动态表单。
4. 需要附件时先创建或选择订单，再通过文件上传入口上传附件并回填 `file_id`。
5. 点击提交订单，订单进入客服审核。

验收关注：

- 文件上传会校验大小、类型和数量。
- 医生只能绑定本人订单下可见且已完成上传的文件。
- 医生端只显示外部状态。

### 病例订单组与多产品

1. 点击“新建订单”，选择已有患者病例。
2. 在“添加产品”中选择一个或多个已发布产品；系统只展示 ACTIVE 配置，不展示草稿/停用材料。
3. 逐个子产品填写动态字段、材料、配件数量和牙位；未配置正式价格时显示“待报价”。
4. 病例/影像共用资料挂订单组，产品专属资料挂对应子订单。
5. 汇总后一次提交；系统为每个产品生成真实子订单编号，后续审核、设计、生产、质检、账单和物流独立流转。

当前限制：

- 客户目录中的未确认价格、交期、文件数量/格式和正式正畸类型继续保持草稿或待报价，不为演示强行发布。

### 我的订单与订单主链路

1. 打开我的订单。
2. 查看订单外部状态、公开消息、设计稿、账单物流和通知。
3. 订单发货后，在账单物流区域查看真实承运商、运单号和物流状态。
4. 只有物流状态为“已发货”或“已送达待确认”时，订单所属医生才能点击确认收货；未发货、无物流记录、非本人订单或重复确认分别按权限/状态门禁拒绝。
5. 确认成功后物流状态冻结为“已送达”，记录送达时间，订单外部状态进入完成并通知客服。

当前限制：

- 付款状态仍需客户 / PM 确认口径。
- 真实物流平台 API 尚未接入。
- 实时自动保存和完整跨设备上传验收尚未完成。

### 设计稿

1. 打开设计稿确认。
2. 查看待确认设计稿版本。
3. 点击预览链接，系统会按文件权限生成短时效签名 URL。
4. 根据实际结果确认或驳回设计稿。

当前限制：

- 三轮驳回 / 重传完整回归仍未完成。
- 在线 CAD 审稿和复杂批注不在一期第一段范围内。

### 账单物流

1. 打开账单物流。
2. 查看账单文件和物流信息。
3. 需要查看账单时获取账单预览链接。
4. 物流达到“已发货 / 已送达待确认”后由订单所属医生确认收货；确认后页面刷新为“已完成”。

当前限制：

- 付款状态和账单金额结构化仍未完成。
- 真实物流平台自动同步不在当前第一段范围内。

### AI 助手

1. 打开订单助手。
2. 只询问订单公开进度、账单、物流和医生可见消息。
3. 涉及内部工序、员工、返工、工时、绩效时，系统应返回安全拒绝。

## 客服端

### 客服初审

1. 进入客服端。
2. 打开内部订单 / 客服初审。
3. 选择待审核订单。
4. 查看资料缺失提示。
5. 可生成 AI 翻译草稿，但必须人工确认后才能写入生产备注。
6. 审核通过后进入生产审核；审核驳回后医生可补资料重新提交。

验收关注：

- AI 只生成草稿，不自动审核、自动发送或自动驳回。
- 驳回原因需要面向医生可理解。

### 协同消息

1. 打开沟通中心。
2. 查看待审核消息。
3. 按订单 ID 查看订单消息上下文。
4. 对生产发给医生的消息执行通过或驳回。

当前限制：

- 完整客服 CRM、客户偏好和复杂工单不在当前第一段范围内。
- 消息附件 URL 聚合和生产级通知联动仍需后续验收。

### 设计稿进度（只读）

1. 打开内部订单设计稿区域。
2. 选择订单后加载已经通过内部技术审核、对医生可见的设计稿版本与业务进度。
3. 获取设计稿文件预览链接。
4. 需要技术判断时联系设计组长处理；客服不能执行设计内审，也不能代医生确认。

## 生产端

当浏览器宽度不超过 980px、左侧导航自动隐藏时，使用顶部“生产端业务菜单”切换已授权页面；该选择器与桌面左侧菜单共用同一权限过滤结果，不会额外暴露未授权入口。

### 生产审核

1. 管理员先在人员管理中为指定生产审核人员授予 `workflow:review-production`；普通技工不授予。
2. 指定审核人员从生产端打开“生产审核”；管理员从管理端“生产审核监控”查看同一队列，只在异常或无人处理时兜底。
3. 选择待生产审核订单。
4. 核对系统按订单产品自动匹配的工序链；若没有匹配链，不得通过审核。
5. 按客户实际提供的资料选择入口路线：STL / PLY 等数字化扫描资料选择“口扫”，实体印模或石膏模型选择“印模”；只支持单一路线的工序链由系统自动锁定。
6. 种植修复选择“成品基台 / 个性化基台”，贴面修复选择“CAD 切削 / 传统蜡型”；存在工艺分支时每组必须选一项。
7. 审核通过后系统生成工序实例快照和 OPEN 设计任务；资料或路线无法确认时必须填写驳回原因并退回。
8. 设计人员领取任务并上传版本，授权组长内审后由医生确认；医生确认会自动完成“设计稿确认”门禁并解锁生产首批节点。

验收关注：

- 普通 WORKER 和 CS 访问审核接口应返回 403；只有被直接授权的 WORKER 和 ADMIN 可处理。
- 审核权限不等于全生产数据权限。除待审核队列外，WORKER 只读取本人被派工节点或本人设计任务关联数据。
- 双入口未选路线、工艺分支缺失、驳回未填原因都应被服务端拒绝。

### 派工与任务池

1. 管理员进入派工页面。
2. 选择尚未派工的生产节点，并绑定启用状态的 WORKER。
3. 已派节点改用转派操作，选择新的启用 WORKER 并填写必填转派原因。
4. 工人进入我的任务，查看本人 READY / IN_PROGRESS / COMPLETED 任务。

验收关注：

- 初次派工、转派分别写入 `workflow_assignment_event`，目标员工收到任务通知。
- 停用账号、非 WORKER、设计确认门禁都不能成为派工目标。
- 普通员工不能读取未分配生产池；管理员在派工页查看全量待派工节点。
- 可选生产节点只能由管理员填写原因后跳过，WORKER 与 CS 均不得执行 skip。

### 入检、工时、出检

1. 工人进入入检 / 出检页面。
2. 对需要入检的节点先提交入检通过。
3. 进入工时记录页面，执行开始、暂停、继续、完成工时。
4. 工序完成后提交出检。
5. 出检通过会推进后续节点；出检失败会创建返工记录。

验收关注：

- 工时按服务端记录计算，暂停段会扣除。
- WORKER 只能查看本人任务和本人绩效。

### 返工终检

1. 打开返工终检。
2. 查看待返工记录。
3. 查看返工影响图，理解返工目标和受影响后续节点。
4. 目标节点重做并出检通过后关闭返工。
5. 具备终检专用权限的账号可生成终检报告。

当前限制：

- 真实电子签章和复杂报告模板尚未接入。
- 医生端不可读取内部终检报告和内部附件。

### 绩效

1. 打开绩效统计。
2. WORKER 默认看本人绩效。
3. ADMIN 可输入员工 ID 查看指定员工绩效。
4. 可使用开始日期和结束日期筛选周期。

当前限制：

- 标准工时维护、版本、审计与实例快照底座已落地，但客户正式分钟未提供，正式运行时默认关闭；页面不显示标准工时、准时率、效率或绩效分的正式结果。申诉、导出和工资发放仍未确认或完成。

## 管理端

### 生产审核监控

1. 打开“生产审核监控”，查看与授权生产审核人员相同的待审队列。
2. 正常订单由生产审核人员处理；管理员只在权限配置错误、审核人员缺席或异常订单无法推进时兜底。
3. 管理员兜底审核仍执行相同的路线、分支和驳回原因校验，不得绕过服务端门禁。

### 产品配置中心

1. 使用具备 `catalog:manage` 的管理账号进入“产品配置中心”。
2. 在草稿版本中维护分类、产品、变体、别名、材料品牌/规格/语义色号、配件、绑定、动态字段、牙位、上传、价格、交期和工序映射。
3. 先预览医生端表单，再由具备 `catalog:publish` 的账号发布；发布后版本不可变。
4. 已发布或已被订单引用的实体只能停用，非法物理删除返回 409；从未发布且未引用的草稿才可物理删除。
5. 停用只影响新草稿，历史订单继续按提交快照展示。

### 标准工时

当前不作为正式菜单入口开放。客户尚未提供正式标准工时，17/19 分钟等浏览器验收值已停用，仅保留技术证据；它们不得用于交期、产能或绩效。

后续启用步骤：

1. 客户提供正式九链节点分钟后，由具备 `workflow:standard-time:manage` 的管理员/工艺管理员通过维护 API 导入到 DRAFT 版本。
2. 完整复核产品、工序链、节点、单位和生效时间；未确认值保持空值，不用演示值补齐。
3. 授权发布、完成部署变更恢复菜单，并由部署负责人显式设置 `WORKFLOW_STANDARD_TIME_FORMAL_ENABLED=true` 后，才启用正式业务计算。
4. 启用后只影响新实例，旧实例和员工实际 `work_log` 不被重写。

注意：底座不提供工序节点增删、排序、拖拽或 DAG 编辑；当前菜单隐藏按用户要求由用户自行查看，不作为本轮自动化/浏览器验收项。

### 动态表单

1. 打开动态表单管理。
2. 新增、编辑或停用字段。
3. 医生端只读取 ACTIVE 字段。

### 返工字典

1. 打开返工字典管理。
2. 新增、编辑或停用返工原因和责任类型。
3. 关闭返工时只能使用 ACTIVE 字典项。

### 通知中心

1. 打开通知中心。
2. 查看未读通知。
3. 可标记单条已读或全部已读。

### 部署与配置

1. 本地开发使用 `.env.example` 和 `compose.yaml`。
2. 一期部署骨架使用 `deploy/docker-compose.phase-one.yml`。
3. 正式环境真实密钥必须外部注入。
4. 不要提交真实数据库密码、MinIO 密钥、DeepSeek API Key 或 webhook secret。
