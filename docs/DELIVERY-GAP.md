## 交付定义（2026-08-04 已确认）

**交付标准 = 一期 38 项验收签字通过。** 按此标准倒排优先级。

| 澄清项 | 结论 | 影响 |

| 上线后运维 | **先我方兜着，稳定后移交客户** | 监控告警按自用标准先做；移交前再补手册与培训签收 |

### ⚠️ 一个必须现在摆出来的矛盾

**i18n 与「前端配 API key」都不在原 38 项验收表内。**

- 只按 38 项签字：这两项不做也能签；
- 但医生是海外客户、看不懂中文 → **签了也用不起来**。

两条路二选一，需要商务决策：

1. **把这两项作为变更单独立项**，与 38 项并列（做法参照 D 批次的 `CA-001`，
   记在 `docs/acceptance/customer-added-requirements-outside-prd-v2-38.md`）；
2. **与客户重新对齐交付定义**，把「医生可用的英文界面」写进验收口径。

不处理的话，验收时会出现「38 项全过但客户说不能用」的局面。

#### 关于 C3（国际化）——这是目前最大的未登记缺口

**它不在任何现有清单里**，因为 PRD 只写了一句「中文优先，i18n 可切换」，
而 38 项验收表里没有对应条目。但客户已明确说**医生是外部客户、配送基本发海外**。

实测数据：

| | 数量 |
| --- | --- |
| 医生端主页面去重中文字符串 | 719 |
| 下单向导去重中文字符串 | 402 |
| 双语函数 `uiText()` 实际调用 | **12** |
| 前端 i18n 框架（vue-i18n 等） | **未引入** |
| 后端返回给医生的中文提示 | 存在（仅下单规则一个包就 20 处） |

**已确认：英文是硬需求。** 需引入 i18n 框架、抽取文案、翻译、并处理后端返回给医生的提示信息。

**好消息是范围可控**：客服端／生产端／管理端是工厂内部使用，保持中文即可，
只有**医生端**需要双语。但后端返回给医生的错误与状态文案也要一并处理。

预计 **2–3 周**（不含专业牙科术语的翻译审校，建议由客户提供术语表）。
