# 生产看板实际工序编排设计

**状态：已确认工艺链来源，待实施**

## 工艺链来源

生产看板以 `backend/platform-server/src/main/resources/db/migration/V2__seed_workflow_chains.sql` 中已启用的 9 条预置工艺链为唯一来源：

- 常规冠修复
- 种植类修复
- 精密附件
- 套筒冠
- 贴面修复
- 活动件-钢托
- 活动件-胶托
- 活动件-隐形
- 正畸

本地测试订单的 `DataScope节点`、`路线X节点` 等名称不参与正式看板列定义。

## 看板结构

### 全厂总览

默认全厂总览按真实 `stage_name` 聚合为从左到右的大工段：下单入厂、收发、取模分支、CAD、种植、基台分支、车金、上瓷、车瓷、钢托、胶托、内冠、外冠、固活焊接、贴面路线、隐形、正畸、收尾。

每个工段固定保留为空列，卡片依据当前工序节点的 `stage_name` 落入对应列。卡片主标题显示当前真实 `process_name`，而不是把工段名重复显示为卡片状态。

### 产品路线视图

增加工艺链选择器。选择某条产品路线后，看板列改为该路线中 `step_order` 的真实节点顺序；取模、口扫、基台、贴面等分支按订单实际实例化的节点显示。这样可以在不混淆全厂视图的前提下查看单一路线的完整生产路径。

## 信息层级

- 日期仍决定看板数据范围，并保留跨日积压订单。
- 顶部摘要按实际工段汇总在制、跨日积压和超时数量，不再以状态标签代替主流程。
- 工序超时、返工、加急显示在订单卡上，并同时计入所属工段的风险数。
- 待生产审核、待派工、医生待确认、终检待发作为流程前后门禁，显示在主工艺列前后，而不是与实际工序混排。

## 验收标准

1. 全厂总览不再出现测试节点作为列标题。
2. 全厂列按真实 `stage_name` 的固定顺序从左到右展示，空列仍保留。
3. 卡片显示当前 `process_name`、负责人、耗时/SLA、到期与风险标签。
4. 选择任一预置工艺链后，列按该链的实际 `step_order` 展开，分支只展示已实例化节点。
5. 日期筛选、关键词筛选、风险筛选、订单详情与现有权限边界保持有效。
