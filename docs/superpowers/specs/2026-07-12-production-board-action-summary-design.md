# 生产看板待办概览设计

**状态：已确认，待实施**

## 目标

将生产看板顶部从混合状态标签改为面向生产主管的待办概览：先看到需要立即处理的风险，再看到当前生产进度，避免“生产异常”这类含义不清的统计。

## 信息结构

顶部概览分为上下两行分组：第一行“需要处理”，第二行“生产进度”。每行左侧显示固定、加大的分组标题，右侧展示可点击的统计入口。

| 分组 | 指标 | 含义 | 优先级 |
| --- | --- | --- | --- |
| 生产进度 | 在制订单 | 当前未出货、未签收的生产订单总数 | 信息参考 |
| 生产进度 | 待派工 | 已创建工序但尚未进入具体工序的订单 | 常规待办 |
| 需要处理 | 工序超时 | 当前工序已超过时限的订单 | 最高 |
| 需要处理 | 返工处理中 | 状态为返工中的订单 | 高 |
| 需要处理 | 医生待确认 | 等待医生确认设计或照片的订单 | 中 |

“生产异常”不再显示。它目前实际指向生产中状态，不能说明异常原因，也不能提供明确的处理入口。

## 视觉与交互

- “需要处理”放在前方，且采用更高对比度；工序超时使用风险色，返工处理中使用警示色，医生待确认保持次级强调。
- “生产进度”位于其后，使用低饱和中性色或现有的进度色，避免与风险争夺注意力。
- 每个指标均为筛选入口：点击后只显示对应订单，当前选中项维持现有激活态。
- 下方按工序的汇总卡不变，继续展示各工序单量、进行中数量和风险数量。

## 数据口径

- 所有数值基于 `productionBoardKanbanCards` 的实时计算结果，不使用固定演示数字。
- 工序超时：`risk === 'overdue'`。
- 返工处理中：`risk === 'rework'` 或订单状态为 `REWORKING`。
- 医生待确认：订单状态为 `PENDING_DOCTOR_CONFIRM` 或 `risk === 'confirm'`。
- 待派工：沿用现有 `PROCESS_INSTANCE_CREATED` 且工序已同步、尚无当前节点的口径。
- 在制订单：沿用当前 `visibleProductionBoardOrders` 的排除已发货、已签收口径。

## 实施范围

- 修改 `frontend/src/App.vue` 中生产看板专用的顶部概览数据与模板，不复用目前同时服务生产审核页的固定 `prototypeQueueChips`。
- 为生产看板新增明确的筛选状态，确保“工序超时”和“返工处理中”点击后能真实过滤，而不是只切换按钮外观。
- 维持生产审核页面的现有标签和行为，避免本次看板调整影响审核工作流。

## 验收标准

1. 顶部按“需要处理”“生产进度”两个分组显示五项实时统计。
2. 不再出现“生产异常”。
3. 工序超时、返工处理中、医生待确认均可点击并准确筛选对应订单。
4. 待派工与在制订单筛选不影响现有日期、关键词和工序列展示。
5. 生产审核页面保持原有概览标签与筛选行为。
6. 前端类型检查、构建和生产看板浏览器交互验证通过。
