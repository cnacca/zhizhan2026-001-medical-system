# 生产看板参考页复刻设计

**状态：已确认，实施中**

## 目标

以 `frontend/public/reference/factory-portal.html` 的生产看板为视觉与交互基准，复刻日期控制、横向工序列、部门摘要、订单卡片及右侧订单抽屉；订单和流程数据继续使用当前真实接口。

## 真实工序数据

- 看板列使用订单流程节点的 `stage_name`，而非测试数据中的 `process_name`。
- 后端流程实例接口补充只读 `stage_name`，前端据此固定展示 V2 工艺链的全厂工段顺序。
- 订单卡片主标题始终显示实际 `process_name`，工段名仅用于列头和汇总。
- 审核、待派工、医生确认、终检待发作为流程前后门禁列，不与生产工段混排。

## 非工序状态展示边界

- `工序待同步` 是前端读取流程实例的技术状态，不作为生产看板列、卡片状态或正式工序展示。
- `工序待映射` 是工艺配置兜底，不作为生产看板列或正式工序展示；实际交付前由真实 `stage_name` 覆盖全部正式工段。
- 流程数据读取异常保留在顶部刷新提示和内部监控中，不伪装成生产节点。
- 空工段仅提示“暂无订单”，不以“积压”描述空列。

## 视觉与交互

- 保持参考页的浅色列底、工段色列头、220px 横向列宽、卡片左侧状态线、紧凑的 11/12px 信息层级及 4px SLA 进度条。
- 卡片显示订单号、产品、诊所/牙位、实际工序、负责人、SLA 进度、风险与同步状态；超时、返工、加急和跨日积压以参考页同层级的醒目标签呈现。
- 每张卡片打开同订单的右侧抽屉；抽屉显示订单摘要、当前工序、实际节点时间轴及已有的终检发货操作。
- 不复制参考 HTML 中的模拟账号、模拟订单或静态仪表盘数据。

## 滚动积压日期口径

- 生产看板按订单去重统计，不按工序节点重复计数。
- 选中日期的“未完成”包含截至该日仍未完成的全部订单；前一日未完成的订单必须自动结转到后一日。
- 在选中日期完成的订单保留在当日“完成”中，从次日起退出生产看板。
- 顶部工段统计、工段列和订单卡片必须使用同一个截至日期快照；“正在进行”调整为“未完成”。
- 待问、内返和超时均按截至选中日期仍未关闭的存量统计，并继续遵循当前账号的 DataScope。

## 验收

1. 看板列不再以 `DataScope节点` 等测试工序作为正式列标题。
2. 看板列按真实工段固定从左到右显示，空列保留。
3. 订单卡片和抽屉的颜色、字体层级、状态提示与参考页一致。
4. 日期、筛选、订单详情、发货操作和现有权限仍然可用。
5. 生产人员页面不展示“工序待同步”或“工序待映射”。
6. 前一日未完成订单在后一日继续展示并计入“未完成”。
7. 当日完成订单在完成日可见，次日不再出现。
